# 03. Сценарии использования

Платформа совместных спортивных активностей (кейс Столото).
Цель документа — собрать максимально широкий набор сценариев, чтобы при проектировании UX не потерять ни одной ветки: ни базовых сценариев проверки S1–S6, ни переходов между ролями, ни краевых случаев, сбоев и злоупотреблений.

Источник требований — бриф задания и критерии оценки кейса. Ссылки вида R-01…R-08 и S1…S6 — на пункты брифа. «Доп.» — сценарий не обязателен по брифу, но вытекает из идей раздела 3 брифа или из анализа рисков.

**Критичность:**
- **must** — без этого не проходит S1–S6 / обязательный минимум R-xx или ломается целостность данных; делаем в прототипе.
- **should** — заметно влияет на оценку UX и «доп. возможности»; делаем, если успеваем, и закладываем в макет.
- **nice** — желательно отразить в макете или в разделе «развитие»; в прототипе — по остаточному принципу.

## 0. Словарь состояний (рабочие названия для UI)

Сценарии опираются на единые состояния. Названия — рабочие, финальные тексты уточняются в макете.

### Мероприятие
| Состояние | Кто переводит | Видно в поиске | Можно записаться |
|---|---|---|---|
| Черновик | автор | нет (только автору) | нет |
| Опубликовано | автор / организация (без модерации) | да | да, если есть места и не началось |
| Опубликовано + флаг «Изменено» / «Перенесено» | автор | да | да |
| Запись закрыта (мест нет / событие началось) | система | да, с пометкой | нет (лист ожидания — опционально) |
| Отменено организатором | автор | нет | нет; карточка по ссылке видна с баннером |
| Снято с публикации администратором | админ | нет | нет; карточка-заглушка, автору видна причина |
| Удалено администратором | админ | нет | нет; по ссылке — «Мероприятие удалено» |
| Завершено (прошло) | система по времени | нет (только в истории) | нет |

### Запись участника
«Вы участник» (подтверждено) · «Заявка на рассмотрении» · «Заявка отклонена» · «В листе ожидания» · «Вы отменили запись» / «Вы отозвали заявку» · «Мероприятие отменено» · «Мероприятие снято с публикации» · «Заявка не рассмотрена» (событие прошло без решения).

### Заявка организации на допуск
Черновик → На рассмотрении → Одобрена / Отклонена (с причиной) / Требует доработки (доп.) → (после доработки) снова На рассмотрении. Для одобренной — опционально «Заблокирована» (доп.).

## 2. Поиск и выбор

### SC-001. Найти игру на вечер по фильтрам
- **Кто / где / триггер:** опытный любитель, телефон, в метро после работы, спешит; сам открыл приложение.
- **Цель:** за пару минут найти футбол сегодня вечером недалеко от дома, где есть места.
- **Шаги:** 1) Открывает ленту. 2) Выбирает направление «Футбол» чипом. 3) Ставит «Сегодня» и район. 4) Включает «Есть свободные места». 5) Открывает карточку.
- **Что может пойти не так → реакция:**
  - Фильтры сбрасываются при возврате из карточки → фильтры и позиция прокрутки сохраняются в адресе страницы и восстанавливаются по «Назад».
  - Непонятно, сколько фильтров активно → строка активных фильтров чипами с крестиком и кнопка «Сбросить всё»; счётчик «Найдено: 7».
  - Список грузится долго на мобильной сети → скелетоны карточек, а не пустой экран.
- **Критичность:** must · **Связь:** S3, R-03

### SC-002. Текстовый поиск с опечатками и синонимами
- **Кто / где / триггер:** опытный любитель, телефон; вводит запрос в строку поиска.
- **Цель:** найти «шахматы», набрав «шахмоты», или «бег», набрав «пробежка».
- **Шаги:** 1) Вводит запрос. 2) Видит подсказки направлений и событий. 3) Выбирает подсказку. 4) Получает выдачу.
- **Что может пойти не так → реакция:**
  - Опечатка даёт ноль результатов → «Показаны результаты для «шахматы». Искать «шахмоты»?»
  - Пользовательское направление записано иначе («Футбол 5х5») → поиск по названию, синонимам каталога и описанию события.
  - Запрос из одной буквы → подсказки показываем с 2 символов, без мигания результатов.
- **Критичность:** must · **Связь:** R-03, R-04

### SC-003. Найти нишевое направление, добавленное пользователями
- **Кто / где / триггер:** любитель петанка, десктоп, есть время; сам ищет.
- **Цель:** понять, есть ли в городе люди, играющие в петанк.
- **Шаги:** 1) Ищет «петанк». 2) Видит направление с пометкой «добавлено участниками» и числом событий. 3) Открывает событие.
- **Что может пойти не так → реакция:**
  - Направления нет вообще → пустое состояние «Пока никто не собирал петанк. Создайте первую встречу — направление появится в каталоге» с кнопкой создания, предзаполненной этим названием.
  - Направление есть, но событий нет (все прошли) → «Последняя встреча была 12 сентября» + «Создать свою».
- **Критичность:** should · **Связь:** R-04, универсальность

### SC-004. Понять условия по карточке мероприятия
- **Кто / где / триггер:** новичок, дома, есть время; открыл карточку из ленты.
- **Цель:** решить, подходит ли встреча: уровень, что взять, сколько стоит, как попасть.
- **Шаги:** 1) Читает заголовок, направление, дату и место. 2) Смотрит блок «Условия участия» (уровень, инвентарь, подготовка, стоимость). 3) Видит режим записи и число мест. 4) Смотрит организатора. 5) Нажимает основное действие.
- **Что может пойти не так → реакция:**
  - Режим записи непонятен → под кнопкой одна строка: «Свободная запись — вы сразу станете участником» или «По заявке — организатор подтвердит участие».
  - Поля условий пустые → пустые поля не показываются, но «Уровень» и «Что взять» всегда выводятся с явным значением «Любой уровень» / «Ничего не нужно».
  - Дата записана как «25.10» → дата словами с днём недели и относительной пометкой: «Суббота, 25 октября, 10:00 · через 3 дня».
  - Кнопка уезжает за экран на телефоне → основное действие закреплено внизу экрана.
- **Критичность:** must · **Связь:** R-03, S3, S4

### SC-005. Универсальность: шахматы, бег и зарядка во дворе в одной ленте
- **Кто / где / триггер:** эксперт жюри, десктоп; открыл прототип без подготовки.
- **Цель:** убедиться, что разные направления живут в одной логике.
- **Шаги:** 1) Открывает ленту без фильтров. 2) Видит события разных направлений, включая нефизические (шахматы) и бесплатные дворовые. 3) Открывает 2–3 карточки.
- **Что может пойти не так → реакция:**
  - Карточка шахмат с полями «инвентарь: мяч» выглядит нелепо → единый шаблон с необязательными полями; подписи нейтральные («Что взять с собой»), а не спортивно-специфичные.
  - Дворовая зарядка без адреса → допускается описание места («Двор дома 15, у турников»).
  - Однообразные обложки → у каждого направления иконка/цвет из каталога; для пользовательского — нейтральная иконка.
- **Критичность:** must · **Связь:** R-04, критерий «универсальность»

### SC-006. Пустая выдача по фильтрам
- **Кто / где / триггер:** новичок, телефон; выбрал редкую комбинацию фильтров.
- **Цель:** не упереться в тупик.
- **Шаги:** 1) Ставит «Волейбол», «Завтра», «Октябрьский район». 2) Получает ноль результатов.
- **Что может пойти не так → реакция:**
  - Голый текст «Ничего не найдено» → пустое состояние с тремя выходами: «Убрать фильтр района (найдётся 4)», «Показать ближайшие даты», «Создать свою встречу» (форма предзаполнена направлением, датой, районом).
- **Критичность:** must · **Связь:** R-03, переход к S1

### SC-007. «Прямо сейчас» на площадке
- **Кто / где / триггер:** профи, на площадке, слабая мобильная связь, спешит.
- **Цель:** найти игру, которая начинается в ближайший час и где не хватает людей.
- **Шаги:** 1) Включает быстрый фильтр «Ближайшие 2 часа». 2) Сортировка по времени начала. 3) Видит метку «Не хватает 2 игроков». 4) Записывается.
- **Что может пойти не так → реакция:**
  - Событие уже началось → в выдаче не показываем начавшиеся либо помечаем «Идёт сейчас, запись закрыта».
  - Связь пропадает → последние загруженные результаты остаются на экране с пометкой «Нет связи, данные на 18:42».
- **Критичность:** should · **Связь:** доп., R-03

### SC-008. Карта и «рядом со мной» без геолокации
- **Кто / где / триггер:** любитель, телефон; переключился на вид «Карта».
- **Цель:** увидеть события поблизости.
- **Шаги:** 1) Нажимает «Карта». 2) Браузер спрашивает геолокацию. 3) Видит метки и список под картой.
- **Что может пойти не так → реакция:**
  - Пользователь запретил геолокацию → карта центрируется на городе из профиля, сообщение «Укажите район вручную», без повторного навязчивого запроса.
  - События без точного адреса (описание места) → не ставим ложную метку; показываем в списке под картой с пометкой «Место указано описанием».
  - На карте 50 меток в одной точке → кластеризация с числом.
- **Критичность:** should · **Связь:** доп. (карта приветствуется)

### SC-009. Страница организации из карточки события
- **Кто / где / триггер:** пользователь, десктоп; нажал на название организатора в карточке.
- **Цель:** понять, кто проводит, и посмотреть другие события клуба.
- **Шаги:** 1) Переходит на страницу организации. 2) Читает описание, направления. 3) Видит список предстоящих событий. 4) Открывает другое событие.
- **Что может пойти не так → реакция:**
  - Организатор — частное лицо → ссылка ведёт на профиль пользователя (демо-данные), тип организатора виден значком «Частный организатор» / «Организация».
  - Организация заблокирована после публикации события → см. SC-070.
- **Критичность:** must · **Связь:** S2 (финальный шаг), R-03

### SC-010. Доверие к частному организатору
- **Кто / где / триггер:** новичок, телефон; сомневается перед записью к незнакомому человеку.
- **Цель:** убедиться, что организатор реальный и встреча состоится.
- **Шаги:** 1) Открывает профиль организатора. 2) Видит «На платформе с …», «Провёл 12 встреч», ближайшие события. 3) Возвращается к карточке.
- **Что может пойти не так → реакция:**
  - Организатор новый, истории нет → нейтральная пометка «Первая встреча этого организатора», без отрицательной окраски.
  - У организатора отменены последние встречи → показываем факт «Отменено 2 из 5 встреч» (доп.).
- **Критичность:** should · **Связь:** доп. (доверие и комфорт)

### SC-011. Родитель ищет занятие для ребёнка
- **Кто / где / триггер:** родитель, телефон, одной рукой на прогулке с ребёнком.
- **Цель:** найти занятие для ребёнка 8 лет в выходные.
- **Шаги:** 1) Включает фильтр «Детям» / указывает возраст. 2) Смотрит условия «Присутствие взрослого обязательно». 3) Записывается.
- **Что может пойти не так → реакция:**
  - Возраст не указан организатором → событие не попадает под детский фильтр; в форме создания поле «Возраст участников» с вариантами «Любой / Дети / Взрослые / с … лет».
  - Непонятно, участвует ли родитель → явная строка «Родитель остаётся на площадке / может уйти».
- **Критичность:** should · **Связь:** доп.

### SC-012. Профи фильтрует по уровню
- **Кто / где / триггер:** профи, десктоп, рутинно.
- **Цель:** не тратить время на встречи для начинающих.
- **Шаги:** 1) Ставит фильтр «Уровень: продвинутый». 2) Сохраняет фильтр по умолчанию в профиле.
- **Что может пойти не так → реакция:**
  - Уровни у разных направлений называются по-разному → единая шкала из 3–4 уровней с короткими пояснениями при наведении/нажатии.
  - Событие «любой уровень» → показывается при любом фильтре уровня (не исчезает).
- **Критичность:** should · **Связь:** R-03

### SC-013. Время события в часовом поясе места
- **Кто / где / триггер:** любитель в командировке (браузер в московском времени), ищет встречу в Красноярске.
- **Цель:** не перепутать время.
- **Шаги:** 1) Открывает карточку красноярского события. 2) Видит время.
- **Что может пойти не так → реакция:**
  - Время показано в поясе браузера, человек приходит на 4 часа раньше/позже → время всегда в поясе места проведения с подписью «по местному времени (Красноярск)»; если пояс браузера отличается — вторая строка «у вас сейчас 14:00, это 18:00 в Красноярске».
- **Критичность:** should · **Связь:** доп. (edge: часовые пояса)

### SC-014. Открыл прошедшее событие
- **Кто / где / триггер:** пользователь, телефон; открыл старую ссылку из переписки.
- **Цель:** понять, что событие было, и найти следующее.
- **Шаги:** 1) Открывает карточку. 2) Видит, что событие завершено.
- **Что может пойти не так → реакция:**
  - Кнопка «Записаться» активна → вместо кнопки статус «Мероприятие прошло 12 октября», кнопка «Похожие встречи» и, если есть, «Следующая встреча этого организатора».
  - Обсуждение продолжается → обсуждение доступно только для чтения.
- **Критичность:** must · **Связь:** жизненный цикл, R-03

### SC-015. Поделиться событием с другом
- **Кто / где / триггер:** участник, телефон; хочет позвать друга через мессенджер.
- **Цель:** отправить ссылку, по которой друг сразу поймёт, что, где и когда.
- **Шаги:** 1) Нажимает «Поделиться». 2) Системное меню телефона / копирование ссылки. 3) Друг открывает ссылку без аккаунта.
- **Что может пойти не так → реакция:**
  - Превью ссылки пустое → у страницы события есть заголовок и описание для превью: название, дата, место.
  - Нет системного меню на десктопе → кнопка «Скопировать ссылку» с подтверждением «Ссылка скопирована».
  - Событие по заявке → по ссылке видна публичная часть, закрытые сведения скрыты (см. SC-032).
- **Критичность:** should · **Связь:** доп. (интеграция: мессенджер)

### SC-016. Отложить решение: избранное и напоминание
- **Кто / где / триггер:** любитель, на работе; нашёл событие, но не уверен в планах.
- **Цель:** вернуться к событию позже.
- **Шаги:** 1) Нажимает «Сохранить». 2) Позже открывает «Сохранённые».
- **Что может пойти не так → реакция:**
  - Пока думал, места закончились → в «Сохранённых» метка «Мест не осталось», событие не исчезает без объяснения.
  - Событие снято → карточка в списке с пометкой «Недоступно».
- **Критичность:** nice · **Связь:** доп.

## 3. Запись

### SC-017. Свободное присоединение (S3)
- **Кто / где / триггер:** новичок, телефон, дома; открыл карточку утренней пробежки со свободной записью.
- **Цель:** сразу стать участником и получить информацию, куда приходить.
- **Шаги:** 1) Читает условия. 2) Нажимает «Записаться». 3) Видит подтверждение «Вы участник». 4) Получает раскрытую орг. информацию (точка сбора, контакт, что взять). 5) Организатор видит его в списке участников.
- **Что может пойти не так → реакция:**
  - Не понятно, что запись уже состоялась → кнопка меняется на статус «Вы участник» с галочкой, рядом «Отменить запись»; всплывающее подтверждение; счётчик мест уменьшается сразу.
  - Пользователь не вошёл → см. SC-105 (вход с возвратом к записи).
  - Организатор не видит нового участника без перезагрузки → список участников обновляется при открытии и по кнопке обновления; новые отмечены «новый».
- **Критичность:** must · **Связь:** S3, R-05, R-06

### SC-018. Запись по заявке — заявку приняли (S4, ветка «принято»)
- **Кто / где / триггер:** любитель, десктоп; событие клуба с режимом «по заявке».
- **Цель:** подать заявку и узнать решение.
- **Шаги:** 1) Нажимает «Подать заявку». 2) Видит статус «Заявка на рассмотрении» и пояснение, что будет дальше. 3) Организатор открывает «Заявки», нажимает «Принять». 4) У пользователя статус «Вы участник», появляется орг. информация и уведомление в приложении. 5) У организатора участник переходит из «Заявки» в «Участники».
- **Что может пойти не так → реакция:**
  - Пользователь думает, что уже записан → статус «на рассмотрении» визуально отличается от «участник» (другая иконка, цвет и текст «Вы ещё не участник — ждём решения организатора»).
  - Организатор принимает сверх лимита → кнопка «Принять» неактивна при отсутствии мест, подсказка «Мест не осталось. Увеличьте лимит или отклоните заявку».
- **Критичность:** must · **Связь:** S4, R-05, R-06

### SC-019. Запись по заявке — заявку отклонили (S4, ветка «отклонено»)
- **Кто / где / триггер:** новичок, телефон; подал заявку на игру продвинутого уровня.
- **Цель:** узнать решение и понять, что делать дальше.
- **Шаги:** 1) Подаёт заявку. 2) Организатор нажимает «Отклонить», по желанию выбирает причину («Уровень не подходит», «Состав набран», свой текст). 3) Пользователь видит «Заявка отклонена» и причину. 4) Видит подборку похожих встреч.
- **Что может пойти не так → реакция:**
  - Отказ без объяснения обижает → причина необязательна, но предлагаются вежливые шаблоны; без причины текст нейтральный «Организатор не смог принять заявку».
  - Пользователь сразу подаёт заявку снова → повторная подача на то же событие недоступна, пояснение «Организатор уже рассмотрел вашу заявку. Можно задать вопрос в обсуждении».
  - Организатор отклонил по ошибке → у организатора есть «Вернуть в рассмотрение» до начала события (доп.).
- **Критичность:** must · **Связь:** S4, R-05, R-06

### SC-020. Сообщение организатору вместе с заявкой
- **Кто / где / триггер:** профи, десктоп; закрытая тренировка требует рассказать об опыте.
- **Цель:** повысить шанс принятия.
- **Шаги:** 1) Нажимает «Подать заявку». 2) Видит необязательное поле «Пара слов организатору» (или вопрос организатора, если задан). 3) Отправляет.
- **Что может пойти не так → реакция:**
  - Поле обязательно, а пользователь не знает, что писать → поле необязательное, с подсказкой-примером; ограничение длины со счётчиком.
  - Организатор не видит текст → текст заявки отображается в карточке заявки рядом с кнопками решения.
- **Критичность:** should · **Связь:** R-05, R-06

### SC-021. Мест нет — лист ожидания
- **Кто / где / триггер:** любитель, телефон; популярная игра, лимит исчерпан.
- **Цель:** попасть, если кто-то откажется.
- **Шаги:** 1) Видит «Мест нет · 3 в листе ожидания». 2) Нажимает «Встать в лист ожидания». 3) Участник отменяет запись. 4) Первый из листа становится участником (свободный режим) или его заявка уходит организатору (режим по заявке). 5) Уведомление в приложении.
- **Что может пойти не так → реакция:**
  - Пользователь путает лист ожидания с записью → статус «В листе ожидания, вы 2-й», без орг. информации.
  - Перевод из листа ожидания за час до начала → уведомление с явной просьбой подтвердить или освободить место (доп.).
- **Критичность:** should · **Связь:** доп. (лимит, лист ожидания)

### SC-022. Гонка за последнее место
- **Кто / где / триггер:** два любителя на телефонах одновременно нажимают «Записаться» на последнее место.
- **Цель:** каждый хочет получить место.
- **Шаги:** 1) Оба видят «Осталось 1 место». 2) Оба нажимают. 3) Сервер принимает первого. 4) Второй получает ответ.
- **Что может пойти не так → реакция:**
  - Оба видят «Вы участник» → проверка лимита только на сервере в одной транзакции; второму: «Последнее место только что заняли. Встать в лист ожидания?» с кнопкой; карточка обновляет счётчик.
- **Критичность:** must · **Связь:** R-05, целостность данных

### SC-023. Двойной клик по «Записаться»
- **Кто / где / триггер:** пожилой пользователь или любой на медленной сети; нажимает кнопку дважды.
- **Цель:** записаться один раз.
- **Шаги:** 1) Нажимает. 2) Ответа нет мгновенно. 3) Нажимает снова.
- **Что может пойти не так → реакция:**
  - Две записи / два места занято / ошибка «уже записан» → кнопка сразу переходит в состояние «Записываем…» и блокируется; повторный запрос сервер обрабатывает как тот же (одна запись на пользователя и событие); итог — одно подтверждение.
- **Критичность:** must · **Связь:** R-05, failure

### SC-024. Отмена записи и отзыв заявки
- **Кто / где / триггер:** любитель, телефон, планы изменились за день до встречи.
- **Цель:** освободить место, не подводя организатора.
- **Шаги:** 1) Открывает «Мои записи» или карточку. 2) Нажимает «Отменить запись» / «Отозвать заявку». 3) Подтверждает в диалоге. 4) Видит «Вы отменили запись». 5) Организатор видит изменение, место освобождается.
- **Что может пойти не так → реакция:**
  - Случайное нажатие → диалог подтверждения с последствием: «Ваше место займёт следующий из листа ожидания»; основная кнопка диалога — «Оставить запись».
  - Повторная запись после отмены → разрешена, если есть места (в режиме по заявке — новая заявка).
  - Отмена после начала → недоступна, кнопки нет.
- **Критичность:** should · **Связь:** R-06, доп. (отмена записи)

### SC-025. Конфликт в расписании
- **Кто / где / триггер:** любитель, десктоп; записывается на событие, пересекающееся по времени с уже имеющейся записью.
- **Цель:** не записаться на две встречи одновременно.
- **Шаги:** 1) Нажимает «Записаться». 2) Видит предупреждение.
- **Что может пойти не так → реакция:**
  - Жёсткий запрет мешает (встречи рядом и короткие) → не блокируем, а предупреждаем: «В это время вы записаны на «Шахматы в парке» (18:00–19:30). Всё равно записаться?»
- **Критичность:** nice · **Связь:** доп. (личный календарь)

### SC-026. Попытка записаться, когда запись закрыта по времени
- **Кто / где / триггер:** профи, на площадке, открыл карточку через 10 минут после начала.
- **Цель:** присоединиться к игре.
- **Шаги:** 1) Открывает карточку. 2) Пытается записаться.
- **Что может пойти не так → реакция:**
  - Кнопка активна, запись проходит в прошлое → после начала события кнопки нет, статус «Мероприятие уже идёт — запись закрыта», ссылка на обсуждение и контакт организатора, если он публичный; сервер также отклоняет запись.
  - Организатор задал «закрыть запись за N часов» → «Запись закрылась в 17:00».
- **Критичность:** should · **Связь:** edge «время прошло»

### SC-027. Прямая ссылка на снятое администратором событие
- **Кто / где / триггер:** гость или пользователь получил ссылку в чате; злоумышленник целенаправленно открывает ссылку снятого события.
- **Цель:** записаться на событие.
- **Шаги:** 1) Открывает ссылку. 2) Видит карточку-заглушку. 3) Пытается записаться (интерфейсом или ручным запросом).
- **Что может пойти не так → реакция:**
  - Карточка выглядит как обычная с кнопкой → вместо кнопки баннер «Мероприятие снято с публикации администратором. Записаться нельзя». Описание скрыто или приглушено; ссылка «Найти похожие».
  - Запрос на запись отправлен напрямую → сервер отвечает отказом, запись не создаётся; интерфейс показывает тот же текст.
  - Для удалённого события → «Мероприятие удалено» без содержимого.
- **Критичность:** must · **Связь:** S6, R-08

### SC-028. Родитель записывает себя и ребёнка
- **Кто / где / триггер:** родитель, телефон; семейная зарядка во дворе с лимитом мест.
- **Цель:** записать двоих одним действием.
- **Шаги:** 1) Нажимает «Записаться». 2) Выбирает «Я + 1 ребёнок». 3) Подтверждает.
- **Что может пойти не так → реакция:**
  - Осталось 1 место, а нужно 2 → «Осталось 1 место. Записать только вас?»; без молчаливого частичного успеха.
  - Организатор не понимает, сколько людей придёт → в списке участников «Анна + 1 ребёнок», счётчик мест учитывает всех.
- **Критичность:** nice · **Связь:** доп.

### SC-029. Автор пытается записаться на своё событие
- **Кто / где / триггер:** организатор-пользователь, открыл свою карточку из поиска.
- **Цель:** проверить, как карточку видят другие.
- **Шаги:** 1) Открывает свою карточку.
- **Что может пойти не так → реакция:**
  - Видна кнопка «Записаться» → автору вместо неё панель «Вы организатор»: «Участники и заявки», «Редактировать», «Отменить мероприятие»; ссылка «Посмотреть как участник» (предпросмотр).
- **Критичность:** should · **Связь:** R-06, переходы ролей

### SC-030. Заявка долго без ответа, событие прошло
- **Кто / где / триггер:** любитель, возвращается в приложение через неделю.
- **Цель:** понять, что стало с заявкой.
- **Шаги:** 1) Открывает «Мои записи». 2) Видит итоговый статус.
- **Что может пойти не так → реакция:**
  - Заявка навсегда «на рассмотрении» → пока событие впереди: «Ожидает решения 3 дня»; организатор видит счётчик необработанных заявок на главной; после начала события статус «Заявка не рассмотрена — мероприятие прошло», организатор больше не может принять.
- **Критичность:** should · **Связь:** R-06, жизненный цикл

### SC-031. Уведомление о решении и орг. информация
- **Кто / где / триггер:** пользователь, телефон, на работе; видит счётчик уведомлений в приложении.
- **Цель:** узнать итог заявки и куда приходить.
- **Шаги:** 1) Открывает центр уведомлений. 2) Видит «Вашу заявку на «Волейбол в субботу» приняли». 3) Переходит в карточку. 4) Видит раскрытую орг. информацию. 5) По желанию добавляет в календарь.
- **Что может пойти не так → реакция:**
  - Уведомление ведёт на общую страницу → ссылка ведёт прямо в карточку, к блоку статуса.
  - Уведомление устарело (событие потом отменили) → при переходе показывается актуальное состояние, а не то, что было в уведомлении.
  - Добавление в календарь → файл календаря с местным временем события (доп.).
- **Критичность:** must · **Связь:** S4, R-06

### SC-032. Сведения, скрытые до подтверждения
- **Кто / где / триггер:** пользователь, десктоп; закрытая тренировка клуба по заявке.
- **Цель:** понять, что получит после принятия.
- **Шаги:** 1) Открывает карточку. 2) Видит общую информацию и закрытый блок. 3) Подаёт заявку.
- **Что может пойти не так → реакция:**
  - Пользователь думает, что информации просто нет → закрытый блок виден как плашка с замком: «Точный адрес и контакт организатора откроются после подтверждения заявки». Район/ориентир показаны всегда.
- **Критичность:** should · **Связь:** R-05, правила доступа

### SC-033. «Мои записи»: все статусы в одном месте
- **Кто / где / триггер:** любой пользователь, телефон; возвращается в приложение.

- **Шаги:** 1) Открывает «Мои записи». 2) Видит группы «Предстоящие», «Ждут решения», «Прошедшие и отменённые».
- **Что может пойти не так → реакция:**

  - Изменилось время → метка «Изменено» на карточке записи.
- **Критичность:** must · **Связь:** R-06

## 4. Создание мероприятия и управление им

### SC-034. Пользователь создаёт мероприятие (S1)
- **Кто / где / триггер:** опытный любитель, десктоп; хочет собрать волейбол в воскресенье.
- **Цель:** опубликовать встречу так, чтобы её нашли.
- **Шаги:** 1) Нажимает «Создать встречу». 2) Заполняет: название, направление, дата и время, место, описание, условия (уровень, что взять, стоимость), режим записи, лимит мест. 3) Смотрит предпросмотр карточки. 4) Публикует. 5) Другой пользователь находит событие поиском и открывает.
- **Что может пойти не так → реакция:**
  - Длинная форма пугает → форма разбита на 3–4 смысловых блока на одном экране (или шагах на телефоне) с прогрессом; необязательные поля помечены «необязательно», а не обязательные звёздочкой.
  - Выбор режима непонятен → две крупные карточки-варианта с описанием последствий: «Свободная запись: люди сразу становятся участниками» / «По заявке: вы решаете, кого принять».
  - После публикации неясно, что дальше → экран успеха: «Встреча опубликована», ссылка на карточку, «Поделиться», «Участники и заявки».
- **Критичность:** must · **Связь:** S1, R-02, R-05

### SC-035. Новое направление, которого нет в каталоге (S1)
- **Кто / где / триггер:** организатор-пользователь, десктоп; собирает диск-гольф.
- **Цель:** указать своё направление и опубликовать.
- **Шаги:** 1) Вводит «диск-гольф» в поле направления. 2) Видит «Нет в каталоге». 3) Нажимает «Добавить «Диск-гольф» как новое направление». 4) Публикует. 5) Направление появляется в фильтрах и поиске у других без изменения кода.
- **Что может пойти не так → реакция:**
  - Пользователь не понимает, можно ли своё → в выпадающем списке последней строкой всегда «Нет моего направления — добавить своё».
  - Новое направление попадает в каталог под видом официального → пометка «добавлено участниками»; админ может объединить его с существующим (доп.).
- **Критичность:** must · **Связь:** S1, R-04

### SC-036. Своё направление с опечаткой или дублем
- **Кто / где / триггер:** организатор, телефон, спешит; вводит «футбик», «Футбол » (с пробелом), «football», «Мини футбол».
- **Цель:** быстро указать направление.
- **Шаги:** 1) Вводит название. 2) Видит подсказку похожих. 3) Выбирает существующее или подтверждает новое.
- **Что может пойти не так → реакция:**
  - Создаётся дубль «футбик» рядом с «Футбол» → нормализация (регистр, пробелы, ё/е), поиск похожих и синонимов: «Возможно, вы имели в виду «Футбол»?» с кнопками «Да, Футбол» и «Нет, это другое направление».
  - Совпадение по регистру/пробелам → молча используется существующее направление, без вопроса.
  - Мусорный ввод («ааааа», ссылка, мат) → ограничение длины и символов, сообщение «Название направления: от 2 до 40 букв».
- **Критичность:** must · **Связь:** R-04, S1

### SC-037. Ошибки при заполнении формы
- **Кто / где / триггер:** любой организатор; ошибся в дате или пропустил поле.
- **Цель:** опубликовать без потери введённого.
- **Шаги:** 1) Заполняет форму. 2) Нажимает «Опубликовать». 3) Получает ошибки.
- **Что может пойти не так → реакция:**
  - Дата в прошлом / окончание раньше начала / лимит 0 / пустое место → ошибка рядом с полем простым языком («Выберите дату не раньше сегодняшней»), фокус и прокрутка к первой ошибке, сводка вверху «Исправьте 2 поля»; введённые данные сохраняются.
  - Ошибка видна только цветом → текст ошибки и иконка, поле связано с текстом ошибки для скринридера.
- **Критичность:** must · **Связь:** S1, R-02

### SC-038. Черновик и прерванное создание
- **Кто / где / триггер:** организатор, телефон; на середине формы позвонили, закрыл вкладку.
- **Цель:** не заполнять всё заново.
- **Шаги:** 1) Начинает форму. 2) Уходит. 3) Возвращается к «Создать встречу».
- **Что может пойти не так → реакция:**
  - Всё потеряно → черновик сохраняется автоматически; при возврате «У вас есть незаконченный черновик от 14:20. Продолжить / Начать заново».
  - Черновик виден другим → черновики видны только автору, в поиске отсутствуют; в «Моих мероприятиях» — метка «Черновик».
- **Критичность:** should · **Связь:** жизненный цикл (черновик)

### SC-039. Создание встречи с телефона в дороге
- **Кто / где / триггер:** организатор, телефон, в автобусе, одна рука.
- **Цель:** за пару минут собрать пробежку на завтра.
- **Шаги:** 1) Создаёт встречу. 2) Пользуется разумными значениями по умолчанию (завтра, длительность 1 час, свободная запись, без лимита). 3) Публикует.
- **Что может пойти не так → реакция:**
  - Мелкие поля даты/времени → системные мобильные выборщики даты и времени; быстрые варианты «Сегодня / Завтра / Суббота».
  - Клавиатура перекрывает кнопку → кнопка действия не перекрывается клавиатурой.
- **Критичность:** should · **Связь:** S1, адаптивность

### SC-040. Не нашёл — создал своё (переход участник → организатор)
- **Кто / где / триггер:** новичок, искал зарядку во дворе, ничего нет.
- **Цель:** собрать соседей самому.
- **Шаги:** 1) Получает пустую выдачу. 2) Нажимает «Создать свою встречу». 3) Форма предзаполнена направлением, датой и районом из фильтров. 4) Публикует. 5) Становится организатором — появляется раздел «Мои мероприятия».
- **Что может пойти не так → реакция:**
  - Пользователь не знает, что может создавать сам → призыв «Не нашли подходящее? Соберите свою компанию» в пустых состояниях и в конце ленты.
  - Боится ответственности → подсказка в форме: «Вы сможете изменить или отменить встречу в любой момент».
- **Критичность:** must · **Связь:** S1, переходы ролей, главная ценность

### SC-041. Повторяющаяся встреча
- **Кто / где / триггер:** организатор дворовой зарядки, десктоп; встреча каждую субботу.
- **Цель:** не создавать событие заново каждую неделю.
- **Шаги:** 1) В форме включает «Повторять: каждую неделю, до 31 декабря». 2) Публикует серию. 3) Каждое занятие — отдельное событие со своей записью.
- **Что может пойти не так → реакция:**
  - Отмена одного занятия отменяет всю серию → при отмене выбор «Только это занятие / Это и все следующие».
  - Запись на серию → запись на каждое занятие отдельно, в карточке «Это занятие из серии «Зарядка по субботам»».
- **Критичность:** nice · **Связь:** доп. (повторяющиеся встречи)

### SC-042. Организатор работает со списком участников и заявок
- **Кто / где / триггер:** организатор-пользователь или организация, десктоп; накопились заявки.
- **Цель:** увидеть, кто идёт, и разобрать заявки.
- **Шаги:** 1) Открывает «Участники и заявки». 2) Видит вкладки «Участники (8/12)», «Заявки (3)», «Лист ожидания (1)». 3) Открывает заявку, читает сообщение. 4) Принимает или отклоняет.
- **Что может пойти не так → реакция:**
  - После решения заявка просто исчезает → короткое подтверждение «Иван принят» с возможностью отмены несколько секунд; счётчики обновляются.
  - Пусто → «Пока никто не записался. Поделитесь ссылкой на встречу» с кнопкой «Поделиться».
  - Свободный режим → вкладки «Заявки» нет, только «Участники».
- **Критичность:** must · **Связь:** R-06, S3, S4

### SC-043. Решение по заявке с телефона из уведомления
- **Кто / где / триггер:** организатор, телефон, в дороге; уведомление «Новая заявка на «Теннис в среду»».
- **Цель:** ответить быстро, не открывая десктоп.
- **Шаги:** 1) Открывает уведомление. 2) Попадает прямо на заявку. 3) Принимает в одно нажатие.
- **Что может пойти не так → реакция:**
  - Уведомление ведёт на главную → глубокая ссылка на конкретную заявку.
  - Заявку уже отозвали → «Пользователь отозвал заявку», кнопки решения скрыты.
- **Критичность:** should · **Связь:** R-06

### SC-044. Изменение времени или места после записи участников
- **Кто / где / триггер:** организатор, десктоп; площадка занята, нужно сдвинуть на час.
- **Цель:** изменить событие и предупредить людей.
- **Шаги:** 1) Нажимает «Редактировать». 2) Меняет время. 3) Видит предупреждение «8 участников получат уведомление об изменении». 4) Сохраняет.
- **Что может пойти не так → реакция:**
  - Участники не замечают изменения → баннер в карточке «Изменено 18 октября: время 19:00 → 20:00», метка «Изменено» в «Моих записях», уведомление в приложении, системное сообщение в обсуждении.
  - Изменены мелочи (опечатка в описании) → уведомлять только при изменении даты, времени, места, режима, условий; в форме видно, какие изменения вызовут уведомление.
- **Критичность:** should · **Связь:** доп. (информирование об изменениях), жизненный цикл

### SC-045. Перенос мероприятия на другую дату
- **Кто / где / триггер:** организатор, телефон; дождь, переносит пробежку на следующую субботу.
- **Цель:** сохранить собранную группу.
- **Шаги:** 1) Нажимает «Перенести». 2) Выбирает новую дату. 3) Указывает причину. 4) Подтверждает.
- **Что может пойти не так → реакция:**
  - Участникам новая дата не подходит → в карточке «Перенесено с 25 на 1 ноября» и кнопка «Не смогу — отменить запись»; запись сохраняется по умолчанию.

- **Критичность:** should · **Связь:** доп. (переносы), жизненный цикл

### SC-046. Организатор отменяет мероприятие
- **Кто / где / триггер:** организатор, телефон, стрессовая ситуация (заболел), за 3 часа до начала.
- **Цель:** быстро отменить и предупредить всех.
- **Шаги:** 1) Нажимает «Отменить мероприятие». 2) Указывает причину (необязательно). 3) Подтверждает. 4) Участники и заявители видят «Мероприятие отменено организатором».
- **Что может пойти не так → реакция:**
  - Случайная отмена → диалог: «Отменить «Футбол в субботу»? 10 участников получат уведомление. Вернуть мероприятие после отмены будет нельзя» — основная кнопка красная с полным текстом действия «Отменить мероприятие».
  - Участники узнают на площадке → баннер в карточке, статус в «Моих записях», уведомление; событие пропадает из поиска; по ссылке видно с баннером.
  - Ожидающие заявки → автоматически получают статус «Мероприятие отменено».
- **Критичность:** must · **Связь:** жизненный цикл, R-06

### SC-047. Уменьшение лимита ниже числа записавшихся
- **Кто / где / триггер:** организатор, десктоп; площадку дали меньшую.
- **Цель:** сократить число мест.
- **Шаги:** 1) Меняет лимит с 16 на 10 при 12 участниках. 2) Сохраняет.
- **Что может пойти не так → реакция:**
  - Система молча удаляет двоих → сохранение блокируется с объяснением «Уже записано 12 человек. Поставьте не меньше 12 или сначала освободите места в списке участников».
  - Увеличение лимита при листе ожидания → «3 человека из листа ожидания станут участниками» (свободный режим).
- **Критичность:** should · **Связь:** доп. (лимит мест)

### SC-048. Смена режима записи после появления участников
- **Кто / где / триггер:** организатор, десктоп; решил перейти со свободной записи на заявки.
- **Цель:** контролировать состав дальше.
- **Шаги:** 1) Меняет режим. 2) Видит предупреждение. 3) Сохраняет.

- **Критичность:** should · **Связь:** R-05

### SC-049. Мероприятие прошло: архив организатора

### SC-050. Организатор в другом часовом поясе

### SC-051. Удаление собственного мероприятия

## 5. Общение

### SC-052. Вопрос в обсуждении и ответ организатора (S5)
- **Кто / где / триггер:** новичок, телефон; не понял, нужны ли шиповки.
- **Цель:** уточнить условия до записи.
- **Шаги:** 1) Открывает вкладку/блок «Обсуждение». 2) Пишет вопрос. 3) Организатор видит уведомление и отвечает на вопрос. 4) Спросивший получает уведомление и видит ответ под своим вопросом.
- **Что может пойти не так → реакция:**
  - Не ясно, кто ответил → у сообщений организатора метка «Организатор» и выделение фона; у автора — его имя и время; у системных сообщений — отдельный стиль.
  - Ответ теряется среди других сообщений → ответ показывается вложенным под вопрос (один уровень вложенности).
  - Пустое обсуждение → «Вопросов пока нет. Спросите организатора о деталях — ответ увидят все».
- **Критичность:** must · **Связь:** S5, R-07

### SC-053. Ответ от имени организации
- **Кто / где / триггер:** представитель одобренного клуба, десктоп; вопрос под событием клуба.
- **Цель:** ответить официально от лица клуба.
- **Шаги:** 1) Открывает событие клуба. 2) Пишет ответ. 3) Ответ подписан «Беговой клуб «Енисей» · Организатор».
- **Что может пойти не так → реакция:**
  - Ответ уходит от личного имени → в поле ответа виден переключатель/подпись «Ответить как: Беговой клуб «Енисей»»; для событий организации по умолчанию — от организации.
- **Критичность:** must · **Связь:** S5, R-07, переходы ролей

### SC-054. Гость читает обсуждение и хочет спросить
- **Кто / где / триггер:** гость без аккаунта, телефон; перешёл по ссылке.
- **Цель:** задать вопрос.
- **Шаги:** 1) Читает обсуждение. 2) Нажимает на поле ввода.
- **Что может пойти не так → реакция:**
  - Поле есть, а отправка падает с ошибкой → вместо поля кнопка «Войдите, чтобы задать вопрос»; после входа возврат к обсуждению с открытым полем и сохранённым черновиком.
- **Критичность:** must · **Связь:** R-07, R-01

### SC-055. Обсуждение события по заявке
- **Кто / где / триггер:** пользователь без подтверждения, десктоп; закрытая тренировка.
- **Цель:** задать вопрос до подачи заявки.
- **Шаги:** 1) Открывает карточку. 2) Видит правило доступа к обсуждению.
- **Что может пойти не так → реакция:**
  - Обсуждение пропало без объяснения → явная плашка с правилом. Рекомендуемое правило: задавать вопросы может любой вошедший пользователь, но организатор может включить «Обсуждение только для участников» — тогда «Обсуждение доступно участникам. Задайте вопрос в заявке».
- **Критичность:** should · **Связь:** R-07, правила доступа

### SC-056. Системные сообщения об изменениях в обсуждении
- **Кто / где / триггер:** участник, телефон; организатор перенёс встречу.
- **Цель:** узнать об изменении там, где он и так читает.
- **Шаги:** 1) Открывает обсуждение. 2) Видит системное сообщение «Время изменено: 19:00 → 20:00».
- **Что может пойти не так → реакция:**
  - Системное сообщение похоже на сообщение человека → отдельный стиль без аватара, с иконкой события.
- **Критичность:** should · **Связь:** R-07, доп. (информирование)

### SC-057. Повторяющиеся вопросы и закреплённый ответ
- **Кто / где / триггер:** организатор популярной встречи; 5 человек спросили одно и то же.
- **Цель:** ответить один раз.
- **Шаги:** 1) Нажимает «Закрепить» на своём ответе. 2) Ответ показывается первым.
- **Что может пойти не так → реакция:**
  - Ответ остаётся внизу → закреплённое сообщение сверху обсуждения с меткой; лучше — предложить организатору перенести ответ в условия карточки («Добавить в описание»).
- **Критичность:** nice · **Связь:** R-07, доп.

### SC-058. Отправка сообщения при плохой связи
- **Кто / где / триггер:** участник, на площадке, связь прерывается.
- **Цель:** отправить вопрос «Где вы стоите?».
- **Шаги:** 1) Пишет. 2) Нажимает «Отправить». 3) Связь пропадает.
- **Что может пойти не так → реакция:**
  - Текст потерян → сообщение остаётся в списке со статусом «Не отправлено · Повторить»; текст в поле не очищается до подтверждения сервером; повторная отправка не создаёт дубля.
- **Критичность:** should · **Связь:** R-07, failure

### SC-059. Редактирование и удаление своего сообщения
- **Кто / где / триггер:** пользователь, ошибся в вопросе.
- **Цель:** исправить.
- **Шаги:** 1) Открывает меню сообщения. 2) Редактирует или удаляет.
- **Что может пойти не так → реакция:**
  - Удаление сообщения с ответом ломает ветку → вместо текста «Сообщение удалено автором», ответ сохраняется; отредактированное помечено «изменено».
- **Критичность:** nice · **Связь:** R-07

### SC-060. Обсуждение отменённого, снятого или прошедшего события
- **Кто / где / триггер:** участник открывает обсуждение события, которое сняли с публикации.
- **Цель:** спросить «что случилось?».
- **Шаги:** 1) Открывает карточку. 2) Переходит к обсуждению.
- **Что может пойти не так → реакция:**
  - Можно писать в снятое событие (поток жалоб без адресата) → обсуждение только для чтения с пояснением: «Обсуждение закрыто: мероприятие снято с публикации». Для снятого админом — обсуждение видно автору, участникам и админу, публично скрыто.
- **Критичность:** should · **Связь:** R-07, S6, жизненный цикл

## 6. Организация

### SC-061. Подача заявки на допуск организации (S2)
- **Кто / где / триггер:** тренер беговой школы, десктоп, на работе; решил разместить клуб.
- **Цель:** получить страницу организации на платформе.
- **Шаги:** 1) В профиле нажимает «Зарегистрировать организацию». 2) Заполняет: название, тип (клуб, кружок, федерация, компания, школа, двор/ЖК, другое), чем занимается, направления, город/район, контакт для администратора, необязательный логотип. 3) Видит предпросмотр будущей страницы. 4) Отправляет. 5) Видит статус «На рассмотрении» и что будет дальше.
- **Что может пойти не так → реакция:**
  - Представитель не понимает срок → на экране статуса: «Администратор рассмотрит заявку. Пока заявка на рассмотрении, страница не видна другим и публиковать от имени организации нельзя».
  - Обязательные поля не заполнены → валидация как в SC-037.
  - Двойная отправка → одна заявка, кнопка блокируется.
- **Критичность:** must · **Связь:** S2, R-01

### SC-062. До одобрения: что можно и что нельзя
- **Кто / где / триггер:** представитель организации, заявка «На рассмотрении»; пытается создать событие.
- **Цель:** опубликовать первое занятие клуба.
- **Шаги:** 1) Нажимает «Создать встречу». 2) Видит выбор «От себя / От организации». 3) Пытается выбрать организацию.
- **Что может пойти не так → реакция:**
  - Кнопка просто не работает → вариант «От организации» неактивен с пояснением «Станет доступно после одобрения заявки. Статус: на рассмотрении»; от себя лично создавать можно.
  - Прямой переход на страницу организации другими пользователями → «Страница не найдена» (не раскрываем неодобренные организации).
  - Ручной запрос публикации от имени организации → отказ сервера (см. SC-082).
- **Критичность:** must · **Связь:** S2, R-02

### SC-063. Организацию одобрили — публикация без согласования (S2, ветка «одобрено»)
- **Кто / где / триггер:** представитель, получил уведомление в приложении «Заявка одобрена».
- **Цель:** опубликовать событие от имени организации.
- **Шаги:** 1) Видит статус «Одобрена» и ссылку на публичную страницу. 2) Создаёт событие «от организации». 3) Публикует — событие сразу в поиске, без повторной модерации. 4) Другой пользователь видит страницу организации и событие на ней.
- **Что может пойти не так → реакция:**
  - Представитель ждёт ещё одной модерации → на экране публикации пояснение «Мероприятия организации публикуются сразу».
  - Страница организации пуста → см. SC-069.
- **Критичность:** must · **Связь:** S2, R-02

### SC-064. Организацию отклонили — причина и повторная подача (S2, ветка «отклонено»)
- **Кто / где / триггер:** представитель, видит уведомление «Заявка отклонена».
- **Цель:** понять причину и исправить.
- **Шаги:** 1) Открывает заявку. 2) Видит причину от администратора («Не указано, чем занимается организация»). 3) Нажимает «Исправить и отправить снова». 4) Форма предзаполнена прошлыми данными. 5) Заявка снова «На рассмотрении».
- **Что может пойти не так → реакция:**
  - Отказ без причины → поле причины для админа обязательно при отклонении; причина видна организации дословно.
  - Повторная подача теряет историю → у заявки виден журнал: подана → отклонена (причина) → подана повторно.
- **Критичность:** must · **Связь:** S2, доп. (причина отклонения)

### SC-065. Заявка возвращена на доработку
- **Кто / где / триггер:** представитель школы; админ просит уточнить.
- **Цель:** дополнить заявку, не начиная заново.
- **Шаги:** 1) Видит статус «Требует доработки» и комментарий. 2) Правит поля. 3) Отправляет.
- **Что может пойти не так → реакция:**
  - Путаница с отказом → статус нейтрального цвета, текст «Администратор просит уточнить: …», поля, требующие правок, подсвечены.
- **Критичность:** should · **Связь:** доп. (возврат на доработку)

### SC-066. Переключение «лично / от имени организации»
- **Кто / где / триггер:** представитель одобренного клуба, который сам ходит на чужие игры.
- **Цель:** не перепутать, от чьего имени действует.
- **Шаги:** 1) Записывается на чужую игру лично. 2) Создаёт событие от клуба. 3) Отвечает в обсуждении от клуба.
- **Что может пойти не так → реакция:**
  - Действие совершено не от того лица → в каждом месте, где важно авторство (создание события, ответ в обсуждении), явный выбор «Как: Вы / Клуб «Енисей»» с аватаром; запись на события — всегда лично.
  - В шапке непонятно, в каком режиме → переключатель контекста в меню профиля с текущим режимом.
- **Критичность:** must · **Связь:** R-01, переходы ролей

### SC-067. Непрофессиональные организации: двор, компания, школа
- **Кто / где / триггер:** активист ЖК, телефон; хочет собирать соседей на зарядку; HR компании — корпоративный забег.
- **Цель:** оформить сообщество, которое не является спортклубом.
- **Шаги:** 1) Выбирает тип «Двор / ЖК» или «Компания». 2) Заполняет минимальные поля. 3) После одобрения публикует события.
- **Что может пойти не так → реакция:**
  - Форма требует «федеральных» данных и отпугивает → поля общие и короткие; тип организации — просто подпись на странице.
  - Корпоративное событие только для сотрудников → режим «по заявке» + пояснение в условиях «Только для сотрудников компании».
- **Критичность:** should · **Связь:** универсальность, R-01

### SC-068. Федерация с множеством событий разных направлений
- **Кто / где / триггер:** представитель федерации, десктоп; ведёт 20 событий.
- **Цель:** управлять событиями организации.
- **Шаги:** 1) Открывает «Мероприятия организации». 2) Фильтрует по статусу (предстоящие, черновики, прошедшие, снятые). 3) Видит счётчики заявок по каждому событию.
- **Что может пойти не так → реакция:**
  - Снятое администратором событие теряется в списке → отдельный статус «Снято администратором» с причиной и меткой в списке.
- **Критичность:** should · **Связь:** R-06

### SC-069. Пустая страница только что одобренной организации
- **Кто / где / триггер:** пользователь открыл страницу нового клуба; событий ещё нет.
- **Цель:** понять, чем занимается клуб.
- **Шаги:** 1) Открывает страницу.
- **Что может пойти не так → реакция:**
  - Пустой экран → описание и направления видны всегда; блок событий: «Ближайших встреч пока нет»; представителю на той же странице — «Создайте первую встречу».
- **Критичность:** should · **Связь:** S2

### SC-070. Организация заблокирована после одобрения
- **Кто / где / триггер:** администратор заблокировал клуб за мошенничество; у клуба 3 события с участниками.
- **Цель (админа):** убрать организацию с платформы.
- **Шаги:** 1) Админ блокирует с причиной. 2) Страница и события скрываются.
- **Что может пойти не так → реакция:**
  - Участники не понимают, куда пропали события → в «Моих записях» статус «Мероприятие снято с публикации», представитель видит причину блокировки.
- **Критичность:** nice · **Связь:** доп. (блокировки)

## 7. Администрирование

### SC-071. Очередь заявок организаций
- **Кто / где / триггер:** администратор, десктоп, рутинно; счётчик «Новых заявок: 3».
- **Цель:** рассмотреть заявки.
- **Шаги:** 1) Открывает раздел «Организации» → «На рассмотрении». 2) Открывает заявку: сведения, дата подачи, история. 3) Нажимает «Одобрить» или «Отклонить» (с обязательной причиной) или «Вернуть на доработку». 4) Заявка уходит из очереди, организация видит результат.
- **Что может пойти не так → реакция:**
  - Решение принято случайно → диалог подтверждения для отклонения; для одобрения — подтверждение с текстом «Страница станет публичной».
  - Очередь пуста → «Новых заявок нет».
  - Решение не меняет данные → после одобрения представитель сразу получает возможность публиковать (проверяется сценарием SC-063).
- **Критичность:** must · **Связь:** S2, R-01

### SC-072. Снятие мероприятия с публикации (S6)
- **Кто / где / триггер:** администратор, десктоп, стрессово; пришла жалоба на событие с рекламой.
- **Цель:** чтобы событие больше не предлагалось для записи.
- **Шаги:** 1) Находит событие. 2) Нажимает «Снять с публикации». 3) Указывает причину. 4) Событие исчезает из поиска и страницы организатора. 5) Организатор видит баннер с причиной. 6) Записавшиеся видят «Мероприятие снято с публикации».
- **Что может пойти не так → реакция:**
  - Записи «висят» → правило: существующие записи переводятся в статус «Мероприятие снято с публикации», новые записи и заявки невозможны; ожидающие заявки закрываются.
  - Организатор пытается снова опубликовать или редактировать → редактирование и повторная публикация заблокированы с текстом «Снято администратором: <причина>».
- **Критичность:** must · **Связь:** S6, R-08

### SC-073. Удаление против снятия
- **Кто / где / триггер:** администратор, явный спам (событие из мусорного аккаунта).
- **Цель:** удалить совсем.
- **Шаги:** 1) Нажимает «Удалить». 2) Видит отличие от снятия. 3) Подтверждает.
- **Что может пойти не так → реакция:**
  - Админ путает действия → в меню два действия с пояснениями: «Снять с публикации — скрыть, можно восстановить» и «Удалить — безвозвратно»; удаление требует подтверждения вводом названия или явным повтором.
  - Участники удалённого события → в «Моих записях» строка «Мероприятие удалено администратором».
- **Критичность:** must · **Связь:** R-08

### SC-074. Поиск и навигация по связям
- **Кто / где / триггер:** администратор, десктоп; разбирает жалобу.
- **Цель:** из события перейти к организатору и обсуждению, из организации — к её событиям.
- **Шаги:** 1) Ищет по названию события или организации. 2) Фильтрует по состоянию. 3) Открывает событие → организатор → его события → обсуждение.
- **Что может пойти не так → реакция:**
  - Поиск не находит снятые и удалённые → в админке фильтр «Все состояния», снятые видны с меткой.
- **Критичность:** must · **Связь:** R-08, админ-контур

### SC-075. Восстановление снятого по ошибке
- **Кто / где / триггер:** администратор, организатор написал, что снятие ошибочно.
- **Цель:** вернуть событие.
- **Шаги:** 1) Находит снятое событие. 2) Нажимает «Вернуть в публикацию». 3) Событие снова в поиске.
- **Что может пойти не так → реакция:**
  - Событие уже прошло → восстановление недоступно, «Мероприятие уже прошло».
  - Бывшие участники → по правилу команды: записи восстанавливаются в прежнем статусе, участники получают уведомление «Мероприятие снова доступно».
- **Критичность:** should · **Связь:** доп. (восстановление)

### SC-076. Скрыть отдельное сообщение в обсуждении
- **Кто / где / триггер:** администратор, жалоба на оскорбление в обсуждении.
- **Цель:** убрать сообщение, не трогая событие.
- **Шаги:** 1) Открывает обсуждение события из админки. 2) Нажимает «Скрыть» у сообщения. 3) Указывает причину.
- **Что может пойти не так → реакция:**
  - Ветка рвётся → на месте сообщения «Сообщение скрыто модератором»; автор видит причину.
- **Критичность:** should · **Связь:** доп. (модерация обсуждений)

### SC-077. Администратор и заявки участников
- **Кто / где / триггер:** администратор, открыл событие по заявке с 5 ожидающими.
- **Цель:** посмотреть состояние события.
- **Шаги:** 1) Открывает событие в админке.
- **Что может пойти не так → реакция:**
  - Админ принимает заявки за организатора → в админке количество участников и заявок видно только для чтения, без кнопок решения (решения принимает автор).
- **Критичность:** should · **Связь:** правило брифа (админ не рассматривает заявки участников)

### SC-078. Два администратора решают одну заявку
- **Кто / где / триггер:** два админа одновременно открыли одну заявку организации.
- **Цель:** принять решение.
- **Шаги:** 1) Первый одобряет. 2) Второй через минуту нажимает «Отклонить».
- **Что может пойти не так → реакция:**
  - Решение перезаписывается → сервер проверяет актуальный статус; второму: «Заявка уже одобрена администратором Мариной в 14:02», экран обновляется.
- **Критичность:** should · **Связь:** целостность данных

### SC-079. Журнал действий администратора
- **Кто / где / триггер:** администратор, разбирается, кто снял событие.
- **Цель:** восстановить историю решений.
- **Шаги:** 1) Открывает «Журнал». 2) Фильтрует по объекту.
- **Что может пойти не так → реакция:**
  - Нет причины в записи → каждая запись: кто, когда, что, над каким объектом, причина.
- **Критичность:** nice · **Связь:** доп. (журнал действий)

### SC-080. Очередь жалоб
- **Кто / где / триггер:** администратор; пользователи жалуются на события и сообщения.
- **Цель:** разобрать жалобы.
- **Шаги:** 1) Открывает «Жалобы». 2) Видит объект, причину, число жалоб. 3) Снимает объект или отклоняет жалобу.
- **Что может пойти не так → реакция:**
  - Несколько жалоб на одно событие засоряют очередь → группировка по объекту со счётчиком.
- **Критичность:** nice · **Связь:** доп. (жалобы)

## 8. Доверие и безопасность

### SC-081. Фейковая организация
- **Кто / где / триггер:** злоумышленник подаёт заявку «Официальный клуб Столото» / «Федерация футбола России».
- **Цель (злоумышленника):** получить доверенную страницу.
- **Шаги:** 1) Подаёт заявку. 2) Ждёт одобрения.
- **Что может пойти не так → реакция:**
  - Страница видна до проверки → неодобренная организация не видна никому, кроме автора и админа.
  - Админу трудно заметить подделку → в карточке заявки подсказки: совпадение названия с существующей организацией, возраст аккаунта, число событий автора; отклонение с причиной.
- **Критичность:** must · **Связь:** S2, доверие

### SC-082. Подмена роли и прямые адреса
- **Кто / где / триггер:** пользователь вручную открывает адрес админки или отправляет запрос на публикацию от имени неодобренной организации / чужого события.
- **Цель (злоумышленника):** получить чужие права.
- **Шаги:** 1) Вводит адрес админки. 2) Отправляет запрос на изменение чужого события.
- **Что может пойти не так → реакция:**
  - Интерфейс скрывает кнопки, но сервер принимает действие → все права проверяются на сервере по текущей роли и состоянию организации; ответ — экран «Нет доступа к этой странице» с кнопкой «На главную», без технических подробностей.
  - Переключатель демо-ролей позволяет выдать себе админа на рабочем стенде → переключатель задаёт демо-аккаунт целиком, а не флаг роли; права всё равно проверяются сервером.
- **Критичность:** must · **Связь:** R-01, правило брифа «упрощение авторизации не распространяется на бизнес-логику»

### SC-083. Спам в обсуждении
- **Кто / где / триггер:** спамер публикует одинаковые сообщения со ссылками под десятками событий.
- **Цель (спамера):** реклама.
- **Шаги:** 1) Пишет сообщения подряд.
- **Что может пойти не так → реакция:**
  - Обсуждения засорены → ограничение частоты: «Слишком часто. Попробуйте через минуту»; повторы одного текста блокируются; кнопка «Пожаловаться» у каждого сообщения; организатор события может скрыть сообщение в своём обсуждении (доп.).
- **Критичность:** should · **Связь:** доп. (модерация обсуждений)

### SC-084. Оскорбления в комментариях
- **Кто / где / триггер:** участник, раздражён, грубит организатору.
- **Цель (пострадавшего):** убрать оскорбление.
- **Шаги:** 1) Нажимает «Пожаловаться». 2) Выбирает причину. 3) Админ скрывает сообщение (SC-076).
- **Что может пойти не так → реакция:**
  - Пожаловавшийся не знает, что дальше → «Спасибо, администратор рассмотрит жалобу»; жалоба на одно сообщение от одного пользователя — один раз.
- **Критичность:** should · **Связь:** доп. (жалобы)

### SC-085. Массовые заявки и захват мест
- **Кто / где / триггер:** злоумышленник или «перестраховщик» записывается на все игры выходных подряд.
- **Цель (злоумышленника):** занять места, сорвать встречи.
- **Шаги:** 1) Записывается на десятки событий подряд.
- **Что может пойти не так → реакция:**
  - Свободные события заполнены фейками → ограничение числа одновременных пересекающихся записей; предупреждение о конфликте (SC-025); организатор может исключить участника из списка с причиной (доп.); при частых неявках — пометка в профиле (развитие).
- **Критичность:** should · **Связь:** доп. (adversarial)

### SC-086. Мошенническое событие с предоплатой
- **Кто / где / триггер:** злоумышленник публикует «тренировку» с требованием перевести деньги на карту.
- **Цель (пользователя):** не попасться.
- **Шаги:** 1) Пользователь видит в описании номер карты. 2) Жалуется. 3) Админ снимает событие.
- **Что может пойти не так → реакция:**
  - Пользователь не знает правил → в блоке «Условия участия» стоимость указывается отдельным полем; рядом подсказка «Платформа не принимает оплату. Будьте осторожны с предоплатой незнакомым людям».
- **Критичность:** should · **Связь:** доп. (доверие)

### SC-087. Приватность участников
- **Кто / где / триггер:** любой пользователь просматривает список участников.
- **Цель (участника):** не раскрывать лишнего незнакомцам.
- **Шаги:** 1) Открывает карточку события.
- **Что может пойти не так → реакция:**
  - Публично видны контакты участников → публично: число участников и, по желанию, имена/аватары; контакты не показываются никому, кроме организатора (и только то, что участник сам указал).
- **Критичность:** should · **Связь:** правила доступа

### SC-088. Массовое создание мусорных событий
- **Кто / где / триггер:** новый аккаунт публикует 30 событий за 5 минут.
- **Цель (спамера):** засорить ленту.
- **Шаги:** 1) Создаёт события подряд.
- **Что может пойти не так → реакция:**
  - Лента засорена → лимит частоты создания для новых аккаунтов: «Можно создать не больше N встреч в час»; администратор может снять все события пользователя одним действием (доп.).
- **Критичность:** nice · **Связь:** доп.

## 9. Доступность

### SC-089. Поиск и запись со скринридером
- **Кто / где / триггер:** незрячий пользователь, десктоп со скринридером / телефон с экранным диктором.
- **Цель:** найти встречу и записаться без зрения.
- **Шаги:** 1) Переходит по заголовкам и ориентирам страницы. 2) Заполняет фильтры. 3) Слушает карточки результатов. 4) Нажимает «Записаться». 5) Слышит результат.
- **Что может пойти не так → реакция:**
  - Кнопки «Подробнее» неотличимы → у кнопок доступные имена с контекстом: «Записаться на «Футбол», суббота 25 октября, 18:00».
  - Результат записи не озвучивается → изменение статуса объявляется автоматически («Вы участник»), фокус не теряется.
  - Иконки без подписей, чипы-фильтры без состояния → у иконок текстовые альтернативы, у чипов — состояние «выбрано».
  - Количество результатов не слышно → объявление «Найдено 7 встреч» после применения фильтров.
- **Критичность:** must · **Связь:** UX-требование брифа (разный цифровой опыт)

### SC-090. Управление с клавиатуры и моторные ограничения
- **Кто / где / триггер:** пользователь с тремором / без мыши, десктоп и телефон.
- **Цель:** пройти запись и создание события без точных движений.
- **Шаги:** 1) Проходит интерфейс клавишей табуляции. 2) Открывает выборщик даты. 3) Подтверждает действия.
- **Что может пойти не так → реакция:**
  - Мелкие цели → зоны нажатия не меньше 44×44 px, промежутки между соседними действиями.
  - Действие только перетаскиванием (карта, сортировка) → всегда есть альтернатива кнопками.
  - Фокус не виден → заметная рамка фокуса; порядок фокуса совпадает с визуальным; диалоги удерживают фокус и закрываются клавишей Esc.
  - Тайм-ауты → нет ограничений по времени на заполнение формы.
- **Критичность:** must · **Связь:** UX-требование брифа

### SC-091. Слабослышащий пользователь
- **Кто / где / триггер:** слабослышащий, телефон; ждёт решения по заявке.
- **Цель:** не пропустить важное.
- **Шаги:** 1) Получает уведомление. 2) Читает статус.
- **Что может пойти не так → реакция:**
  - Сигналы только звуком → вся информация дублируется визуально: счётчик уведомлений, баннеры, статусы; в описании события можно указать «Есть сурдоперевод / организатор общается письменно» (доп.).
  - Контакт организатора только телефоном → можно указать мессенджер или «писать в обсуждении».
- **Критичность:** should · **Связь:** доп. (доступность)

### SC-092. Пожилой человек: крупный шрифт и простые формулировки
- **Кто / где / триггер:** пользователь 60+, планшет с увеличенным системным шрифтом (200%).
- **Цель:** прочитать карточку и записаться.
- **Шаги:** 1) Открывает карточку. 2) Читает условия. 3) Записывается.
- **Что может пойти не так → реакция:**
  - Вёрстка ломается при увеличении → тексты в относительных единицах, переносы строк, без горизонтальной прокрутки; кнопки растут вместе с текстом.
  - Жаргон («слот», «апрув», «ивент», «оффер») → простые слова: «место», «заявка принята», «встреча».
  - Серый мелкий текст → контраст текста не ниже 4.5:1, основной текст не меньше 16 px.
  - Иконка без подписи → ключевые действия всегда с текстом.
- **Критичность:** must · **Связь:** UX-требование брифа (старшее поколение)

### SC-093. Статусы не только цветом
- **Кто / где / триггер:** пользователь с нарушением цветовосприятия, телефон.
- **Цель:** отличить «принято» от «отклонено» и «на рассмотрении».
- **Шаги:** 1) Открывает «Мои записи».
- **Что может пойти не так → реакция:**
  - Зелёный и красный неразличимы → каждый статус: иконка + текст + цвет; форма бейджа одинаково читается в ч/б.
- **Критичность:** must · **Связь:** R-06 (статус понятен)

### SC-094. Доступность площадки
- **Кто / где / триггер:** пользователь на коляске, ищет настольный теннис.
- **Цель:** найти встречу, куда он сможет попасть.
- **Шаги:** 1) Включает фильтр «Доступно для маломобильных». 2) Читает описание входа.
- **Что может пойти не так → реакция:**
  - Информации нет → поле в форме создания «Доступность места» (пандус, лифт, ровный вход, «не знаю»); без указания — «Организатор не указал доступность», а не «недоступно».
- **Критичность:** nice · **Связь:** доп.

### SC-095. Помощник действует за пожилого человека
- **Кто / где / триггер:** внучка с телефоном бабушки записывает её на скандинавскую ходьбу.
- **Цель:** записать правильного человека и передать понятную информацию.
- **Шаги:** 1) Записывает. 2) Показывает бабушке экран «Вы участник» с орг. информацией.
- **Что может пойти не так → реакция:**
  - Бабушка не найдёт информацию потом → на экране подтверждения крупно: когда, куда, что взять; кнопка «Сохранить в календарь» / «Поделиться» (переслать себе).
- **Критичность:** nice · **Связь:** доп.

### SC-096. Яркое солнце и шум на площадке
- **Кто / где / триггер:** участник на улице, экран в бликах, вокруг шумно.
- **Цель:** быстро посмотреть точку сбора и время.
- **Шаги:** 1) Открывает «Мои записи» → ближайшая встреча.
- **Что может пойти не так → реакция:**
  - Низкий контраст и мелкий текст → ключевая информация ближайшей записи вынесена крупно наверх: время, место, контакт; высокий контраст; ничего не сообщается звуком.
- **Критичность:** should · **Связь:** доп.

## 10. Сбои

### SC-097. Потеря связи при записи
- **Кто / где / триггер:** любитель, телефон, в метро; нажал «Записаться», связь пропала.
- **Цель:** понять, записан он или нет.
- **Шаги:** 1) Нажимает «Записаться». 2) Запрос не доходит.
- **Что может пойти не так → реакция:**
  - Ложный успех или вечная загрузка → через короткое время: «Нет связи. Запись не отправлена» + «Повторить»; кнопка возвращается в исходное состояние; ни одного оптимистичного «Вы участник» без ответа сервера.
  - Запрос дошёл, а ответ потерян → повтор безопасен (одна запись, см. SC-023), при повторе показывается актуальный статус.
- **Критичность:** must · **Связь:** failure, R-05

### SC-098. Ошибка сервера при публикации события
- **Кто / где / триггер:** организатор, заполнил большую форму, нажал «Опубликовать».
- **Цель:** опубликовать без повторного ввода.
- **Шаги:** 1) Нажимает «Опубликовать». 2) Сервер возвращает ошибку.
- **Что может пойти не так → реакция:**
  - Форма очищена → данные остаются в форме, сообщение «Не удалось опубликовать. Ваши данные сохранены. Попробовать снова»; черновик сохранён.
- **Критичность:** must · **Связь:** S1, failure

### SC-099. Устаревший экран: событие изменилось, пока карточка была открыта
- **Кто / где / триггер:** пользователь держал карточку открытой час; за это время событие сняли / места кончились / время перенесли.
- **Цель:** записаться.
- **Шаги:** 1) Нажимает «Записаться» на устаревшем экране.
- **Что может пойти не так → реакция:**
  - Запись проходит на снятое событие → сервер проверяет актуальное состояние; ответ с понятной причиной: «Мероприятие снято с публикации» / «Мест не осталось» / «Время изменилось на 20:00 — проверьте и подтвердите»; карточка перерисовывается в актуальное состояние.
- **Критичность:** must · **Связь:** S6, R-05

### SC-100. Сессия истекла во время заполнения
- **Кто / где / триггер:** организатор заполнял форму 40 минут, сессия истекла.
- **Цель:** опубликовать.
- **Шаги:** 1) Нажимает «Опубликовать». 2) Получает требование войти.
- **Что может пойти не так → реакция:**
  - Данные потеряны после входа → вход в диалоге поверх формы или с возвратом; форма восстанавливается из черновика.
- **Критичность:** should · **Связь:** failure

### SC-101. Битая или несуществующая ссылка
- **Кто / где / триггер:** гость, ссылка с опечаткой или на удалённое событие.
- **Цель:** найти то, что искал.
- **Шаги:** 1) Открывает ссылку.
- **Что может пойти не так → реакция:**
  - Техническая ошибка → дружелюбная страница «Такой страницы нет» со строкой поиска и ссылкой на ленту; для удалённого события — «Мероприятие удалено» (отличаем от опечатки).
- **Критичность:** should · **Связь:** failure

### SC-102. Возвращение после офлайна: статусы изменились
- **Кто / где / триггер:** пользователь не заходил 3 дня; за это время его заявку приняли, а другое событие перенесли.
- **Цель:** узнать, что изменилось.
- **Шаги:** 1) Открывает приложение. 2) Видит счётчик уведомлений.

### SC-105. Гость пытается записаться — вход с возвратом к действию
- **Кто / где / триггер:** гость, телефон; перешёл по ссылке друга на событие.
- **Цель:** записаться как можно быстрее.
- **Шаги:** 1) Читает карточку без аккаунта. 2) Нажимает «Записаться». 3) Видит вход/регистрацию. 4) Входит. 5) Возвращается в ту же карточку, действие продолжено (подтверждение записи в один шаг).
- **Что может пойти не так → реакция:**
  - После входа пользователь попадает на главную → возврат на исходную карточку и продолжение действия.
  - Запись происходит молча после входа → после возврата явное подтверждение «Записаться на «…»?» (пользователь мог передумать).
  - За время входа места кончились → сообщение по SC-099.
- **Критичность:** must · **Связь:** R-01, R-03, S3

### SC-106. Регистрация и вход (имитация, но с экранами)
- **Кто / где / триггер:** новый пользователь, любой экран.
- **Цель:** создать аккаунт.
- **Шаги:** 1) Нажимает «Войти». 2) Выбирает «Регистрация». 3) Указывает имя и контакт. 4) Попадает в онбординг.
- **Что может пойти не так → реакция:**
  - Длинная регистрация → минимум полей (имя + контакт), остальное — потом в профиле.
  - Понятно, что это имитация → на демо-стенде пометка «Демо-вход: подтверждение не требуется» (честно отделяем имитацию от работающего).
- **Критичность:** must · **Связь:** R-01

### SC-107. Проверяющий: демо-доступы и переключение ролей
- **Кто / где / триггер:** эксперт жюри, десктоп, спешит; открыл ссылку на прототип.
- **Цель:** пройти S1–S6 без ручной подготовки данных.
- **Шаги:** 1) На экране входа видит блок «Демо-доступ»: пользователь, второй пользователь, организация до одобрения, одобренная организация, администратор. 2) Входит одной кнопкой. 3) Переключается между ролями через меню профиля. 4) Видит, что действия одной роли меняют данные у другой.
- **Что может пойти не так → реакция:**
  - Непонятно, какой аккаунт для чего → у каждой кнопки подпись: «Анна — участник, есть записи и заявки», «Клуб «Енисей» — организация на рассмотрении» и т. п.
  - Данные «испорчены» прошлым проверяющим → кнопка «Сбросить демо-данные» (доп.) либо достаточно исходных объектов для повторного прохождения каждой ветки.
  - В шапке не видно текущей роли → постоянная пометка текущего аккаунта и роли.
- **Критичность:** must · **Связь:** S1–S6, R-01, требования к сдаче

### SC-108. Онбординг новичка: интересы и район
- **Кто / где / триггер:** новичок сразу после регистрации.
- **Цель:** получить подходящую ленту.
- **Шаги:** 1) Выбирает 1–5 направлений чипами. 2) Указывает уровень «Только начинаю». 3) Указывает район. 4) Видит персональную подборку.
- **Что может пойти не так → реакция:**
  - Онбординг мешает → кнопка «Пропустить», шагов не больше трёх, всё меняется позже в профиле.
  - Подборка пуста → пустое состояние SC-006 + «Показать все встречи».
- **Критичность:** should · **Связь:** доп. (персональная подборка)

### SC-109. Пожилой человек впервые по ссылке от внука
- **Кто / где / триггер:** пользователь 60+, телефон, получил ссылку на скандинавскую ходьбу в мессенджере.
- **Цель:** понять, что это, и записаться.
- **Шаги:** 1) Открывает ссылку. 2) Читает карточку. 3) Нажимает крупную кнопку. 4) Проходит вход. 5) Видит понятное подтверждение.
- **Что может пойти не так → реакция:**
  - Всплывающие окна (куки, подписки, онбординг) перекрывают карточку → при входе по ссылке на событие карточка показывается первой, без онбординга и навязчивых окон.
  - Непонятно, получилось ли → полноэкранное или крупное подтверждение: «Вы записаны. Суббота, 25 октября, 10:00. Сбор у входа в парк. Что взять: удобную обувь».
- **Критичность:** must · **Связь:** UX-требование брифа (старшее поколение)

### SC-110. Первый шаг в незнакомую компанию
- **Кто / где / триггер:** новичок-интроверт, дома; боится прийти к незнакомым людям.

- **Что может пойти не так → реакция:**
  - Организатор не заполнил блок → поле в форме создания с подсказкой «Как вас узнать на месте?»; если пусто — блок не показывается.
  - Человек не понимает уровень → метка «Подходит новичкам» ставится организатором явно.

### SC-111. Возвращающийся пользователь
- **Кто / где / триггер:** пользователь, не заходил месяц, открыл главную.

- **Что может пойти не так → реакция:**

- **Критичность:** should · **Связь:** доп.

### SC-112. Будущий представитель организации ищет, как разместить клуб
- **Кто / где / триггер:** руководитель шахматного кружка, десктоп; впервые на платформе.

- **Шаги:** 1) Видит в подвале/меню «Для клубов и организаций». 2) Читает короткое объяснение: что даёт страница, что нужна проверка администратором. 3) Регистрируется как пользователь. 4) Подаёт заявку организации (SC-061).

  - Ищет «регистрацию организации» как отдельный тип аккаунта → объяснение: «Сначала войдите как человек, затем создайте страницу организации — вы будете её представителем».
- **Критичность:** should · **Связь:** R-01, переходы ролей
