# Оплата на сайте (ЮKassa)

> Текущее решение владельца от 03.11.2026: оплата полностью отключена (`PAYMENTS_PROVIDER=disabled`, `PAYMENTS_ENABLED=false`). Ключи магазина и выплат удаляются из рабочего окружения и копий конфигурации. Создание платежей, тестовая оплата, выплаты, возвраты через сайт и платёжная очередь заблокированы; финансовая история сохраняется. Ниже — описание реализованного, но не включённого платёжного контура, а не обещание действующей услуги. Включение требует отдельного решения и приёмки внешнего шлюза.

Деньги принимает платформа через ЮKassa и передаёт организаторам и продавцам. Чтобы платформа не
теряла на комиссиях, к цене добавляется «сбор сервиса»: он покрывает комиссию ЮKassa и выплаты, а
с продажи вещей — ещё 5% платформе. Человек всегда видит, из чего сложилась сумма.

## Где платят

| Что | Как сейчас | С оплатой на сайте |
| --- | --- | --- |
| Встреча «N ₽ с человека» | перевод или на месте | организатор выбирает «Оплата на сайте»; при записи — оплата, место держится 20 минут |
| Встреча по заявке, платная | — | платят после одобрения заявки, 24 часа на оплату |
| Складчина «на всех N ₽» | делят вручную | карта: деньги замораживаются (холд) на макс. долю, в момент сбора списывается итоговая доля, остаток размораживается; СБП: списывается текущая доля, разница возвращается после сбора |
| Порог «соберёмся, если придут 8» | — | не набрали порог — холды снимаются, оплаты по СБП возвращаются целиком |
| Вещь на полке «Продаю за N ₽» | только обмен | покупатель платит; деньги ждут, пока он нажмёт «Получил» (или 3 дня), потом выплата продавцу |

Оплата на сайте — выбор организатора. По умолчанию у встреч остаётся «на месте или переводом»: все
прежние сценарии работают без оплаты.

## Сбор сервиса: выходим в ноль

Обозначения: `B` — сумма, которую должен получить организатор или продавец; `r` — комиссия ЮKassa за
приём выбранным способом; `p`, `f` — процент и фикс за выплату получателю; `m` — наценка платформы
(0 для встреч, 5% цены для вещей).

```
Итого к оплате T = ceil_руб( (B·(1 + p) + f + m·B) / (1 − r) )
Сбор сервиса    = T − B
```

Округление вверх до рубля: остаток копеек идёт в резерв на возвраты.

Ставки по умолчанию (меняются в админке «Оплата → Ставки», вписать из договора с ЮKassa). По
открытому тарифу ЮKassa карты — 2,8% + 1% за чек при «Чеках от ЮKassa», СБП — индивидуально
(обычно не больше 0,7%):

| Способ | r | Пример: доля 300 ₽ | Пример: вещь 1000 ₽ (+5%) |
| --- | --- | --- | --- |
| СБП | 0,7% | 303 ₽ (сбор 3 ₽) | 1058 ₽ (сбор 58 ₽) |
| Банковская карта, с чеками ЮKassa | 3,8% | 312 ₽ (сбор 12 ₽) | 1092 ₽ (сбор 92 ₽) |
| Банковская карта, без чеков | 2,8% | 309 ₽ (сбор 9 ₽) | 1081 ₽ (сбор 81 ₽) |

Факты ЮKassa, на которые опирается схема: холд по карте до 7 дней, по СБП холда нет; списать с
холда можно меньшую сумму, остаток вернётся сам; снятие холда комиссии не стоит; не списанный
вовремя холд ЮKassa отменяет сама (`expired_on_capture`).

Выплата: `p = 0`, `f = 0` по умолчанию (указать тариф «Выплат» ЮKassa, если подключены).
Способ оплаты человек выбирает на сайте: сразу видно, что СБП дешевле.

ЮKassa не возвращает комиссию при возврате. Поэтому:
- для складчины и порога — холд на карте (двухстадийный платёж): снятый холд ничего не стоит;
- отмена организатором — полный возврат участнику, сбор возвращается тоже (потеря платформы);
- отмена участником по правилам отмены — возвращается доля, сбор сервиса не возвращается.

## Как устроено

- Сервер: `backend/app/payments/` — клиент ЮKassa (API v3), расчёт сбора, платежи, возвраты,
  выплаты, уведомления. Доменные правила (кто может платить, места, статусы, балансы) — в
  `backend/app/domain/features/payments.py`.
- Провайдер: `yookassa` (ключи в окружении) или `fake` — встроенная тестовая страница оплаты
  без списания денег (разработка и стенд без ключей).
- Платёж ЮKassa: `POST /v3/payments` с `Idempotence-Key`, `confirmation: redirect`,
  `return_url = {SITE_URL}/pay/return?payment=…`, `metadata` с нашим id, `payment_method_data.type`
  (`bank_card` или `sbp`), `capture: false` для холда (только карта). Списание `…/capture` (можно
  меньшую сумму), снятие холда `…/cancel`, возврат `POST /v3/refunds`.
- Уведомления: `POST /api/payments/yookassa/webhook`. Статус всегда перепроверяется запросом
  `GET /v3/payments/{id}`: подделать уведомление нельзя.
- Холд по карте живёт до 7 дней, поэтому оплата складчины открывается за 7 дней до встречи.
- Баланс получателя: зачисляется после встречи (или после «Получил» для вещи); выплата по СБП
  через ЮKassa «Выплаты», если подключены, иначе администратор переводит и отмечает вручную.
- Чеки 54-ФЗ: при включённых «Чеках от ЮKassa» к платежу прикладывается `receipt`.

## Что указать в ЮKassa

Пошагово — `docs/features/payments-yookassa-setup.md`: магазин, ключи, адрес уведомлений, холд, чеки,
«Выплаты», ставки в админке.

## Решения по правилам

- **Онлайн-оплата — только для цены «с человека» и складчины.** Включить её можно, пока на встречу
  никто не записан в состав; выключить или поменять цену — пока нет оплат. Иначе суммы у
  записавшихся разошлись бы с карточкой.
- **Складчина с оплатой на сайте требует порог** («соберёмся, если придут N»). По порогу считается
  наибольшая доля `ceil(сумма / порог)`: её замораживают по карте и её же списывают по СБП. Если
  списывать «текущую долю», после ухода части людей деньги пришлось бы добирать, а дописать
  платёж нельзя. После сбора итоговая доля `ceil(сумма / оплатившие)` не больше наибольшей.
- **Сбор складчины** — за 2 часа до начала. Неоплатившие к этому моменту снимаются с записи.
  Оплатили не меньше порога — по карте списывается итоговая доля (остаток размораживается сам),
  по СБП возвращается разница. Меньше порога — все холды снимаются, оплаты по СБП возвращаются
  целиком, организатор получает уведомление. Встречу платформа сама не отменяет.
- **Кто записался после сбора**, платит итоговую долю сразу (без холда). Эти деньги получает
  организатор: как если бы человек пришёл и скинулся на месте.
- **Цена возврата разницы по СБП.** ЮKassa не возвращает комиссию с возвращённой части: это 0,7%
  от разницы между наибольшей и итоговой долей (с разницы 150 ₽ — около рубля). Это небольшая потеря
  платформы; её частично покрывает резерв от округления. По карте потерь нет: снятый холд бесплатен.
- **Срок оплаты.** Свободная запись — 20 минут от записи, по заявке — 24 часа от одобрения,
  складчина — до сбора; не позже начала встречи. Не оплатил — запись снимается, как отмена, место
  переходит листу ожидания. Начатая оплата (человек на странице банка) получает ещё 15 минут.
- **Отмена участником** по правилам отмены — возвращается доля, сбор сервиса нет (он ушёл на
  комиссию банка). Позже срока — без возврата, деньги получит организатор; в складчине такой
  человек считается оплатившим. «Не смогу в новое время» после переноса — полный возврат.
- **Полный возврат со сбором**: организатор отменил встречу, убрал человека из участников,
  администратор удалил встречу; встреча, снятая модератором и не возвращённая до начала. Оплата,
  пришедшая после снятия записи (например, после срока), тоже возвращается целиком.
- **Зачисление** организатору — после окончания встречи: по каждому платежу
  `списано − возвращено − сбор`. Продавцу — после «Получил» или через 3 дня после оплаты.
- **Вещь «Продаю».** При покупке количество на полке сразу уменьшается (резерв), отмена или
  неоплата за 20 минут возвращает его. Получено и на полке не осталось штук — вещь убирается с
  полки. Убрать вещь с открытым заказом нельзя.
- **Баланс** получателя: пользователь или организация (выводит владелец организации).
  Доступно = зачислено − выплаты (кроме неудачных). Ожидает = оплаченные доли предстоящих встреч
  и оплаченные заказы до «Получил».
- **Деньги видят**: плательщик — свои платежи; организатор и соуправляющие — деньги своей
  встречи; владелец — баланс; администратор — всё, может вернуть деньги вручную.
- **Настройки** (`settings.payments` доменных данных) переживают сброс демо-данных, как настройки
  помощника.

## Контракт API

Все адреса — от `/api`. Ответы и ошибки — в формате контракта (`{ code, statusCode, message, errors? }`).
Типы — `frontend/src/types/payments.ts`, адреса и формула сбора — `frontend/src/lib/payments.ts`.
Правила — `backend/app/domain/features/payments.py`; маршруты, которые ходят в ЮKassa, —
`backend/app/api/routes/payments.py`.

### Встреча

| Запрос | Ответ |
| --- | --- |
| `POST /events`, `PUT /events/:id` — поле `paymentMode: 'offline' \| 'online'` | `422 validation` с `errors.paymentMode`: онлайн у бесплатной встречи, складчина без порога, включение при записанных, выключение или смена цены при оплатах |
| `GET /events/:id` — `paymentMode`, `payCollect` (итог сбора складчины), `my.payment: MyPayment` | статусы `not_yet` (открытие `opensAt`), `required` (до `dueAt`), `pending`, `held`, `paid`, `refunded`, `canceled`, `expired`; `canPay`, `hint` |
| `GET /events/:id/money` → `EventMoneyView` | организатор, соуправляющие, администратор; иначе `403 forbidden` |

### Платежи

| Запрос | Ответ |
| --- | --- |
| `GET /payments/quote?kind=event_share&targetId=<событие>` | `QuoteView`: строки по способам (`base`, `fee`, `total`, `feeParts`, `flow`). Гостю тоже |
| `GET /payments/quote?kind=item_order&targetId=<вещь>&quantity=N` | то же с наценкой 5% |
| `POST /payments { kind, targetId, method }` → `PaymentView` | создаёт платёж и `confirmationUrl` (ЮKassa или `/pay/fake/<id>`). Повтор, пока платёж ждёт, возвращает начатый платёж тем же способом. Ошибки: `401`, `404`, `403 forbidden` (чужой заказ), `409 payment_not_required` (уже оплачено, не в составе, встреча без оплаты на сайте), `409 payment_not_open` (складчина: рано), `409 payment_closed` (срок вышел, встреча началась), `422 validation` (способ), `502 payment_provider_error` |
| `GET /payments/:id` → `PaymentView` | владелец или администратор (иначе `404 not_found`). Сервер перезапрашивает статус в ЮKassa, если платёж ещё ждёт |
| `POST /payments/:id/fake { outcome: 'succeeded' \| 'canceled' }` | только провайдер `fake`, только владелец; иначе `403 forbidden` |
| `GET /me/payments` → `PaymentView[]` | |
| `POST /payments/yookassa/webhook` | только сервер. Всегда `200`; статус берётся перезапросом объекта в ЮKassa |

`PaymentView.status`: `pending → held → paid`, `pending → paid`, `pending → canceled | expired`,
`held → canceled`, `paid → partially_refunded → refunded`. `processing: true` — операция ушла в
ЮKassa и ждёт ответа.

### Вещи с полки

| Запрос | Ответ |
| --- | --- |
| `POST /shelf`, `PUT /shelf/:id` — поле `sale: { price } \| null` | `422 validation` с `errors.sale` (цена от 50 до 300 000 ₽) |
| `POST /shelf/:id/buy { quantity }` → `OrderView` | `409 not_for_sale`, `409 full` (нет столько штук), `400 bad_request` (своя вещь), `403` администратор |
| `GET /orders?role=buyer\|seller` → `OrderView[]`, `GET /orders/:id` | покупатель, продавец (владелец вещи) и администратор |
| `POST /orders/:id/received` | покупатель, заказ `paid` → `received`, деньги продавцу |
| `POST /orders/:id/cancel { reason? }` | покупатель или продавец до получения; оплаченный — полный возврат со сбором |

Оплата заказа — `POST /payments { kind: 'item_order', targetId: <заказ>, method }`.

### Балансы и выплаты

| Запрос | Ответ |
| --- | --- |
| `GET /me/balances` → `BalanceSummary[]` | свой баланс и балансы организаций, где пользователь владелец |
| `GET /me/balance?owner=user:u-1\|org:o-1` → `BalanceView` | владелец или администратор |
| `POST /me/payouts { owner, amount?, phone, bankId }` → `PayoutView` | `422 validation` (`errors.phone`, `errors.bankId`, `errors.amount`: больше доступного, меньше `minPayout`) |
| `GET /payments/sbp-banks` → `SbpBank[]` | |
| `GET /payments/settings` → `PaymentSettings` | ставки и сроки для подсказки `quote()` в форме; всем, без входа |

### Администратор

| Запрос | Ответ |
| --- | --- |
| `GET /admin/payments/overview` → `PaymentsOverview` | оборот, комиссия банка, сбор, наценка, резерв, должны получателям, выплаты к переводу, статус подключения ЮKassa |
| `GET /admin/payments?status=&kind=&q=` → `AdminPaymentView[]`, `GET /admin/payments/:id` | |
| `POST /admin/payments/:id/refund { amount?, reason }` | возврат (холд снимается); `422 reason_required`, `422 validation` — сумма больше возможной |
| `GET /admin/payouts?status=` → `PayoutView[]` | |
| `POST /admin/payouts/:id/done { note? }`, `POST /admin/payouts/:id/fail { reason }` | ручной путь: «Переведено», «Не получилось» (деньги снова доступны) |
| `GET /admin/payments/settings`, `PUT /admin/payments/settings` → `PaymentSettings` | ставки, наценка, сроки |

### Уведомления

`pay_due` «Оплатите участие до…», `pay_received` «Оплата получена», `pay_refund` «Деньги вернутся
на карту» (и «Списания не будет» для снятого холда), `pay_expired` «Запись отменена: оплата не
пришла», `pay_collected` «Складчина собрана», `pay_failed` «Порог не набрался», `order_paid`
«Покупатель оплатил вещь» (продавцу), `order_done` «Покупатель получил вещь», `order_canceled`,
`money_credited` «Деньги зачислены», `payout_sent` «Выплата отправлена», `payout_failed`.

### Переменные окружения

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `PAYMENTS_PROVIDER` | `fake` | `fake` — встроенная тестовая страница, `yookassa` — настоящий шлюз |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | пусто | магазин ЮKassa; ключ `test_…` — тестовый магазин |
| `YOOKASSA_RECEIPTS` | `false` | прикладывать чек 54-ФЗ (`receipt`) |
| `YOOKASSA_TAX_SYSTEM_CODE` | пусто | система налогообложения для чека (1–6) |
| `YOOKASSA_VAT_CODE` | `1` | ставка НДС позиции чека (1 — без НДС) |
| `YOOKASSA_PAYOUT_AGENT_ID`, `YOOKASSA_PAYOUT_SECRET_KEY` | пусто | шлюз «Выплаты»; пусто — выплаты переводит администратор |
| `YOOKASSA_CHECK_IP` | `false` | принимать уведомления только с адресов ЮKassa (за nginx — по `X-Real-IP`) |

`return_url` = `{SITE_URL}/pay/return?payment=<наш id>`.
