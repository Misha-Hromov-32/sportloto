# Подборка дня

Раз в день человек получает уведомление «Подборка дня: 3 встречи для вас» с названиями встреч. По нажатию открывается страница `/digest/:id`: карточки ленты с подписью, чем встреча подходит. Отдельно искать ничего не нужно.

**Откуда встречи.** Сначала из «Для вас» в городе человека, затем, если не набралось трёх, ближайшие открытые встречи по его интересам. Только предстоящие в ближайшие 7 дней, куда можно записаться и где есть места. Встречи из прошлых подборок не повторяются. Если подходящих нет, подборка не приходит.

**Настройки** (`/settings#settings-digest`): включить или выключить, время 8:00, 12:00 или 18:00 по поясу города, копия на почту. «На сайте» работает всегда, «На почту» включается только для настоящей подтверждённой почты. Кнопка «Прислать подборку сейчас» собирает подборку сразу: так её удобно показать. У демо-аккаунтов подборка включена на 8:00.

**Письмо.** До трёх карточек: название, когда, где, почему подходит, ссылка. Внизу ссылка «Отписаться»: она выключает подборку без входа на сайт (`/digest/unsubscribe?token=…`). Если в настройках помощника выбрана готовая модель, она пишет короткое вступление к письму (ждём до 20 секунд). При любой ошибке остаётся обычный текст «Мы подобрали встречи по вашим интересам и району».

**Как устроено на сервере.** Правило (`domain/features/digest.py`) срабатывает в фоновой проверке раз в 15 секунд и при любом изменяющем запросе: наступил час человека, а сегодня подборки ещё не было. Правило только создаёт уведомление и ставит письмо в очередь. Письмо отправляет фоновая задача `services/digest_mail.py`: она просыпается по живому обновлению уведомлений и раз в минуту, берёт очередь, пишет и отправляет письмо, отмечает итог. Ссылки в письме строятся от `SITE_URL`.

Контракт — раздел «Подборка дня» в `docs/architecture/api.md`.
