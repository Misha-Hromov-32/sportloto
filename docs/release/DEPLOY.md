# Публикация

Рабочие данные хранятся в PostgreSQL. Настройки и ключи задаются на сервере в `deploy/.env`,
который не входит в Git. Перед обновлением сохраняйте дамп базы и идентификаторы текущих образов.

## Запуск

```sh
cp deploy/.env.example deploy/.env
docker compose -f deploy/docker-compose.yml up -d --build --wait
```

До запуска задайте собственный пароль базы, `SITE_URL`, почту и `COOKIE_SECURE=true` для HTTPS.
Контейнер `web` должен быть доступен только внешнему nginx, например через порт
`127.0.0.1:8095:80`. Не публикуйте PostgreSQL, почтовый интерфейс и тестовый стенд наружу.

Production принудительно отключает `DEMO_LOGIN_ENABLED`, `DEMO_RESET_ENABLED`,
`DEMO_SEED_ON_START` и `DEMO_SHIFT_DATES`, даже если они ошибочно включены в окружении.
Пустая production-база не получает демо-аккаунтов. Существующие моковые записи при обычном
запуске сохраняются. Не запускайте восстановление или сброс демоданных на рабочей базе.

## Защита внешнего nginx

`deploy/nginx-auth-limit.conf` подключается в контексте `http` внешнего nginx.
`deploy/nginx-auth-location.conf` — внутри HTTPS-блока `server` домена сайта, до других
регулярных `location`. В этом файле указан upstream `127.0.0.1:8095`; при другом порте измените его.

Ограничение попыток входа и регистрации: 10 запросов в минуту с одного IP с допустимым
кратковременным всплеском 20 запросов. Ответ при превышении — 429 с `Retry-After`.
Ключ ограничения — адрес TCP-клиента, а не присланный посетителем `X-Forwarded-For`.
Если перед nginx есть CDN, отдельно настройте доверенные адреса прокси и real IP.

Контейнерный nginx подключает `deploy/security-headers.conf`: HSTS, запрет MIME-sniffing,
ограничение встраивания, referrer policy и permissions policy. CSP в этом файле ограничивает
встраивание, объекты и базовый URL; полной политики источников скриптов и стилей здесь пока нет.

После изменений проверяйте `nginx -t`, затем перечитывайте конфигурацию.

## Проверка выпуска

- `/api/health` отвечает 200 и сообщает `database: ok`.
- `/api/demo/accounts` возвращает пустой массив.
- Административные API не доступны гостю.
- Вход администратора требует пароль; пустой пароль и демовход отвергаются.
- SMS и платежи отключены, если это предусмотрено настройками рабочего сайта.
- Каталог, изображения, полка и просьбы о помощи загружаются во всех трёх городах.
- Защитные заголовки присутствуют у HTML, API и статических файлов.

Проверки, меняющие записи, выполняйте на отдельной базе с тестовыми аккаунтами.
Получение уведомления проверяется на настоящем ящике, устройстве или в диалоге VK;
успешный API-ответ сам по себе доставку не подтверждает.

## Обновление и откат

Соберите новые образы до переключения контейнеров. Проверьте их на отдельной тестовой базе.
Сохраните предыдущие образы под отдельными тегами и резервную копию исходников. При изменении
схемы базы заранее определите совместимость отката и порядок восстановления дампа.

После переключения проверьте здоровье базы, публичные страницы и журналы ошибок. Если выпуск
неработоспособен, верните предыдущие образы и конфигурацию внешнего nginx.

```sh
docker compose -f deploy/docker-compose.yml down
```

Эта команда останавливает сервисы и сохраняет тома. `down --volumes` удаляет данные томов;
для штатного обновления и остановки она не нужна.
