# Работа над проектом

Ошибки и предложения собираем в [Issues](https://github.com/Misha-Hromov-32/sportloto/issues).
Перед новой задачей проверьте, нет ли уже похожей. Для ошибки укажите шаги воспроизведения,
ожидаемый результат, браузер и город. Для предложения опишите, кому и в какой ситуации оно поможет.

Об уязвимостях сообщайте по [инструкции безопасности](SECURITY.md), без публикации подробностей в Issues.

## Изменения в коде

1. Создайте ветку от `main` или форк репозитория.
2. Решите одну задачу. Связанные изменения интерфейса, API и документации включите в один pull request.
3. Выполните проверки затронутой части проекта. Команды запуска есть в [README](README.md#проверки).
4. Опишите результат и способ проверки. Для изменения интерфейса приложите снимки до и после,
   включая узкий экран. Укажите номер задачи, если она есть.

Проверки сервера пересоздают схему: используйте отдельную тестовую базу.
Действующие ключи, `.env`, дампы, журналы с персональными данными и загруженные пользователями
файлы в репозиторий не добавляйте. Примеры настроек храните с вымышленными значениями.

Если меняется схема базы, добавьте миграцию Alembic и опишите порядок обновления.
Проверки GitHub Actions должны пройти до слияния. Автоматического развёртывания из pull request нет.

## Общение

Обсуждайте поведение продукта и конкретный код. Критика должна помогать исправить проблему;
оскорбления, травля и публикация чужих личных данных недопустимы.
