# Мост чат-бота на компьютере

Программа держит постоянное WebSocket-соединение с сайтом, отвечает на вопросы чат-бота и рисует
обложки встреч через Codex CLI на этом компьютере. Сайт сам собирает подсказку (база знаний, профиль человека, подборка
встреч) и проверяет ответ. Мост только передаёт вопрос в Codex и возвращает JSON.

Если мост выключен или не ответил вовремя, чат отвечает без модели: поиск, запись и создание
встреч от моста не зависят.

## Что нужно

- Windows, macOS или Linux, Node.js 22 или новее (в нём уже есть WebSocket, зависимости не ставятся).
- Codex, в который выполнен вход. Мост сам найдёт `codex.exe` из приложения Codex для Windows
  (`%LOCALAPPDATA%\OpenAI\Codex\bin\…`) или `codex` в PATH. Путь можно задать в `codexPath`.

## Настройка

1. На сайте войдите администратором, откройте «Админка → Чат-бот помощник», выберите режим
   «Мост на компьютере», нажмите «Сохранить» и «Выпустить ключ моста». Скопируйте ключ.
2. Скопируйте `config.example.json` в `config.json` и вставьте ключ в поле `key`.
   `config.json` в репозиторий не попадает.
3. Проверьте Codex: `node codex-bridge.mjs --once "Как записаться на встречу?"`.
   Проверка рисования: `node codex-bridge.mjs --image "пляжный волейбол на острове Татышев"` —
   через минуту рядом появится `cover.png` (в репозиторий он не попадает).
4. Проверьте мост в окне: `start.cmd` (или `node codex-bridge.mjs`). В журнале появится
   «подключён к wss://…», а в админке — «Подключено».

## Постоянная работа (Windows)

```powershell
powershell -ExecutionPolicy Bypass -File install-autostart.ps1
```

Скрипт регистрирует задачу планировщика `SportBridge`: мост запускается при входе в Windows и
перезапускается через минуту, если упал. Соединение с сайтом восстанавливается само.
Журнал: `logs\bridge.log`. Убрать из автозапуска: `uninstall-autostart.ps1`.

## Настройки `config.json`

| Поле | Что значит |
| --- | --- |
| `server` | Адрес сайта: `wss://sport.up-point.tech/api/assistant/bridge` |
| `key` | Ключ моста из админки |
| `name` | Как компьютер называется в админке |
| `codexPath` | Путь к Codex, если не нашёлся сам |
| `model` | Модель Codex (пусто — по умолчанию из настроек Codex) |
| `reasoningEffort` | `low` отвечает быстрее всего (около 8–10 секунд) |
| `concurrency` | Сколько вопросов обрабатывать одновременно |

То же можно задать переменными окружения `BRIDGE_SERVER`, `BRIDGE_KEY`, `BRIDGE_NAME`,
`CODEX_PATH`, `CODEX_MODEL`.

## Обложки встреч (с версии 1.1.0)

При создании встречи кнопка «Нарисовать обложку» отправляет мосту задание `task: "image"`.
Codex рисует картинку встроенным инструментом генерации изображений (около минуты), мост
возвращает PNG, а сайт открывает его в окне выбора кадра, как загруженное фото.
Кнопка видна, только когда подключён мост версии 1.1.0 или новее. После обновления файла моста
перезапустите задачу, иначе работает старая версия:

```powershell
Stop-ScheduledTask SportBridge
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | ? { $_.CommandLine -like '*codex-bridge.mjs*' } | % { Stop-Process -Id $_.ProcessId -Force }
Start-ScheduledTask SportBridge
```

В `logs\bridge.log` должна появиться строка «мост 1.1.0».

## Безопасность

- Codex запускается в пустой временной папке, в режиме только чтения, без сохранения сессии.
  Для обложки — в свежей пустой папке с записью только в неё; мост читает оттуда один `cover.png`,
  проверяет, что это PNG до 8 МБ, и удаляет папку. Текст встречи передаётся как описание
  в кавычках, с запретом что-либо выполнять. Сайт рисует не чаще 3 раз за 10 минут на человека.
- Ключ моста хранится на сервере только в виде хеша. Новый ключ отменяет старый.
- Действия (создать встречу, записаться) модель только предлагает: выполняет их сайт после того,
  как человек нажмёт «Подтвердить», с его правами.

Протокол сообщений описан в `backend/app/assistant/bridge.py`, схема ответа — `reply.schema.json`
(собирается из `backend/app/assistant/prompt.py`).
